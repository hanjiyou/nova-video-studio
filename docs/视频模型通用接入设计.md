# 视频模型通用接入设计

> 2026-11-05 VG04真实尝试：已按用户授权沿用现有multipart候选，文生和单图各请求1秒、各一次真实POST；两次均被中转以HTTP500 get_channel_failed拒绝，auto分组无该模型可用渠道。因此接口是否兼容及1秒是否支持仍未验证，不开放正式配置。详见[实测记录](implementation/Seedance一秒文生与图生实测.md)。

日期：2026-11-02。当前状态：VG01–VG03及VG05的源码与定向离线验证已完成；VG04因中转协议未确认保留待接入。实现见[配置规则实施记录](implementation/视频模型集中配置规则实施记录.md)。已发布3.6.11未包含本次修复，既有真实验证记录保持。此前“全部行为配置化”的绝对表述由本稿替代。

## 1. 评估结论与建议边界

保留当前按型号集中配置的做法。模型较多、接口和参数差异较大，本轮不建设依赖自动推断的能力发现系统，不依靠模型名称、通用openai标签或试错请求判断支持范围。

**建议采用“集中型号配置 + 版本化协议适配器 + 通用任务流程”。型号的开放开关、模式和参数差异由配置统一表达；实际通信与解析由受测试的适配器实现，各层不再重复维护型号白名单。最终可用能力取配置声明、适配器已实现能力与应用约束的交集。配置不能单独创造尚未实现的能力。**

本修订替代初稿中“新型号继承连接默认协议后可自动开放”的方向。新型号即使与已接入型号共用接口，也须明确登记配置；有配置、配置允许且输入合格才可提交。上游目录负责可见性，用户勾选负责显示偏好，二者均不代替生成配置。

目标是在现有适配器已覆盖其完整协议与素材语义的前提下，新增兼容型号只补一处配置，不再同时修改界面、任务入口、驱动、插件表单等多个型号白名单。对于随程序打包的配置，新型号配置进入安装包仍需正常构建交付；本轮不承诺热更新或无需发包，也不额外增加远端能力接口、外部配置导入或用户维护接口规则的复杂页面。

### 评估依据

实施前问题确实是重复判定：驱动的MODELS数组、任务入口的MODELS.includes、前端参数回退，以及能力登记各自保留型号/规格知识。仅在model-rules.json增加新型号仍可能被其他层拦住，因此集中配置有直接收益；本批已统一配置路径，历史兼容注册表单独隔离。

但现有驱动还实现了multipart原图上传、id/task_id冲突处理、状态解析与/videos/{id}/content取回。这些是协议实现，移入一套任意字段映射或表达式系统会新增解释器、调试和测试负担；某些模型还可能要求先上传素材再生成，简单配置开关无法替代这些程序。

历史受控验证与旧任务恢复中的严格范围也有实际目的。第一批应保持其行为、版本及证据，不为“代码中不能出现型号字符串”的形式目标强行重写。确有必要时在独立批次迁移，重新验证恢复链路。

因此不推荐全自动能力识别，也不推荐建立能配置任意协议的通用引擎。当前应先服务于Grok和首个新型号Seedance，出现第二种协议后再抽取已经证实的共同部分。

## 2. 集中配置与协议代码的分工

沿用并扩展现有backend/connections/model-rules.json及相关集中规则结构，登记完整型号与适用服务范围。共用请求格式由版本化协议适配器实现；型号条目引用适配器，并配置其已支持的模式、参数及简单字段策略。相同参数可以复用配置模板，但不得仅靠名称前缀自动授权未登记型号。

本地服务将型号配置与适配器能力合并成有效能力后返回界面；字段类型、范围、素材数量等采用共享校验规则。配置引用不存在的驱动、驱动不支持的模式或矛盾参数时明确报错，不对外宣称可用。前端提供即时反馈，本地服务在提交和执行时做最终校验，不能靠前端传来的可用标志放行。

| 业务行为 | 配置应覆盖的内容 | 代码的职责 |
| --- | --- | --- |
| 型号与分类 | 完整model、服务范围、媒体类别、必要的声明式分类规则 | 查找配置、核对目录与用户覆盖，不在代码中另写品牌正则授予能力 |
| 开放、显示与默认 | submissionEnabled、默认型号、预设条目；显示偏好仍按连接保存 | 读取有效配置和用户选择，不保留另一份固定Grok列表 |
| 模式 | 文生、单图、有序多图、首尾帧等明确模式 | 按配置判定所选模式，不能把有序参考当成首尾帧 |
| 参数 | 字段类型、必填项、范围、候选值、默认值、是否省略 | 按规则校验与展示，不暗中补6秒、固定尺寸或额外字段 |
| 素材 | 最少/最多数量、格式、顺序和字段映射 | 保留原图及顺序；供应商限制与应用统一资源预算共同校验 |
| 估价 | 当前型号/规格适用的价格数据或明确未知 | 按配置估算；未知时显示暂无报价，不借用Grok费率 |
| 提交与查询 | 引用的协议驱动及版本、驱动支持的简单参数策略 | 适配器负责上传、提交编码、ID解析和状态转换；model来自快照，不在各层复制品牌分支 |
| 成品取回 | 型号所绑定的协议与允许的选项 | 适配器实现content端点或结果地址解析；通用下载器检查每跳来源、凭据和真实媒体 |
| 验证标签 | 配置允许提交与真实证据分别登记 | 可提交但未实测时如实提示，不伪造验证，也不额外按型号封锁 |
| 历史兼容 | 原任务冻结的能力/适配器版本与历史事实 | 保留隔离且受测试的旧版本兼容逻辑，不借用新配置扩大旧任务范围 |

代码必须保留协议实现、任务状态转换、鉴权、幂等和文件完整性校验。型号的简单差异优先配置；复杂差异通过配置选择相应适配器或处理策略。要避免的是界面、入口、驱动各自判断同一个型号，不能把“零特殊代码”作为目标。隔离的旧版本或受控验证分支可保留严格范围，需有明确用途和回归测试，不能成为新增任务绕过配置的暗门。

协议配置只能引用已注册驱动及其受校验字段，不接受任意脚本、任意鉴权头或任意外部指令。若现有驱动确实无法表达新通信机制，则新增协议驱动；驱动按协议标识分派，不能再次按型号判断。

## 3. 全链路排查范围

当前源码核对发现，不能只修改生成按钮或把一个MODELS数组搬进JSON。实施时须一起处理：

1. frontend/src/lib/workbench-client.ts、backend/connections/capabilities.js中的重复预设列表、默认项和按预设序号定位型号。
2. frontend/src/lib/workbench-generation.ts中的默认6秒和参考模式固定1280x720回退；workbench-model-catalog中的参数与开放判断。
3. backend/tasks/workbench-input.js中的MODELS.includes、固定秒数/尺寸/字段数量与参考图模式限制。
4. backend/plugins/opensosen-video/index.js中提交、查询的型号数组、指定型号特判、固定参数和输入字段；manifest.json、ui.schema.json中的重复型号及参数。插件对外投影须由同一配置派生或在构建时生成，不能形成独立来源。
5. backend/connections/service.js、model-catalog.js、capabilities.js中的分类、开放资格、默认型号、能力登记和证据绑定。
6. backend/tasks/video-policy.js、multi-reference-policy及受控验证/旧任务兼容通道中的型号相关条件。先区分重复业务限制与必要的历史/授权范围；前者统一来源，后者第一批保留版本隔离与行为。不得为迁移配置修改已应用迁移、旧快照或旧证据。
7. 新任务的模型选择、按钮、参数、提交、查询和下载必须使用相符的有效能力。仍可调用的旧入口应明确限定其兼容版本，不允许绕过新任务规则。

配置里的型号键、测试夹具和历史证据中出现完整型号是正常数据；验收针对运行时业务逻辑是否另写型号规则，不能仅凭全仓文本搜索没有型号字符串来判定完成。

## 4. 生成按钮与界面

保留现有设置和生成页布局，不要求用户学习或维护底层接口配置。模型选项、参数范围、提示和提交资格由有效配置驱动；支持的模式与当前输入不匹配时保留原输入并说明原因。

| 条件 | 按钮及提示 |
| --- | --- |
| 已登记、已开放，当前模式与输入均合格 | 可以生成 |
| 上述条件满足，但没有真实成功证据 | 可以生成，标注当前组合未实测 |
| 目录存在但未登记生成配置 | 灰色，明确提示该型号尚未配置接入 |
| 配置明确关闭或当前模式不支持 | 灰色，显示具体关闭/模式原因 |
| 配置引用的适配器不存在或尚未实现所需能力 | 灰色，提示需接入协议，不能仅改开放开关解决 |
| 缺描述、素材不合格、参数越界或正在保存等 | 按现有通用规则拦截并说明原因 |

未实测不单独阻止配置已明确开放的型号，也不能让明确关闭的Preview意外开放。新目录型号仍默认隐藏，用户勾选与默认选择政策保持；隐藏不影响已经创建的任务恢复。

## 5. 版本与历史任务

继续复用capabilityVersionId、连接版本和不可变任务快照。配置改动只影响新的生成意图，现有任务仍按原model、原参数、原素材顺序、原协议/能力版本执行，不借用新配置或新凭据。

Grok的新任务可变规则逐项集中配置并做等价回归；旧任务仍按原版本恢复，旧验证门闩不在第一批强行泛化。新通用路径不能暗中补旧默认，旧兼容路径只能服务于匹配的历史版本。真实验证记录仅证明对应服务、模式和参数组合，不因规则重构扩大范围。

未知报价不阻止生成；网络或单次输入错误不永久禁用型号。提交失败不自动改参数、换协议、换型号或重发POST。查询、下载、取消、截止、并发与原子保存沿用现有机制。

## 6. 新增Seedance的方式

先核对当前中转的接口文档或脱敏请求样例，明确实际支持模式、必需参数、参考素材字段、查询状态和成品取回方式。然后为doubao-seedance-2.0-mini登记配置，引用适用协议；不在业务代码追加Seedance判断。

同协议且现有配置结构能表达时，只补型号配置即可。若协议不同，先补通用协议驱动及字段定义，再在配置中引用。不能只增加一行开放开关而忽略驱动能力；未确认的参数、价格与素材语义不猜测。当前已登记Seedance的视频分类和protocol-unconfirmed原因，未绑定驱动，未开放真实生成。

VG01–VG03已按上述边界实现，VG05已用两个未出现在业务代码中的虚构型号验证配置驱动的HTTP提交、查询与完整成品保存，并补旧任务快照和界面回归。VG04仍待中转接口事实；模拟验收不代替Seedance真实接入。此次未使用子代理，未提交、推送、构建安装包或发布。

必须在已实现协议与素材语义范围内做端到端回归：新增两个业务代码从未出现过的虚构型号，仅修改配置，型号候选、模式/参数、按钮、后端校验、实际model和字段、查询及成品取回都正确；再只修改配置中的开放开关、时长、素材限制和价格，确认全链路同步变化。未登记型号不能因同名家族或同协议自动开放。另须验证把配置改为驱动尚未支持的首尾帧或其他模式时明确拒绝，不能把“配置能写”误当成“功能已实现”。虚构型号测试证明通用链路，不替代Seedance真实接口核对和实际验收。
