# 安装包差量更新：状态、诊断与主进程接入

日期：2026-10-27。对应[专项计划](../安装包差量更新修复计划.md) U02。状态：实现及本子任务离线验证完成，交主会话审核；本报告不代表专项整体或真实安装验收完成。主会话负责中央计划、契约、台账及整批结论。

## 1. 已实现行为

设置页沿用现有应用更新面板，增加可选的 downloadMode、fallbackReason、baselineReason，旧状态与旧前端兼容。IPC 仍使用原有无参受信接口，不增加路径、地址或安装参数入口。

| 状态 | 确认依据 | 页面文案 |
| --- | --- | --- |
| preparing | 本次下载刚开始、正在检查安装基础包 | 正在准备更新下载 |
| differential-attempt | 锁定版本开始获取差量索引的日志 | 正在尝试差量更新；尚未确认差量下载 |
| differential | 本次尝试差量后收到 transferred 大于 0 的实际下载回调 | 正在下载差量更新 |
| full | 本次基础包检查返回不可信，禁用本次差量 | 正在下载完整安装包；说明基础包不可用 |
| full-fallback | 上游明确记录差量失败并转完整下载 | 已回退为完整包下载 |
| cached | 已验证完整缓存的日志，随后匹配版本的 update-downloaded | 已复用完整安装包缓存 |
| unknown/缺失 | 有进度但没有可确认方式的证据，或旧版状态 | 正在下载更新 |

单纯 started、拼接计划、没有 fallback、收到完成事件均不证明使用差量或节省流量。缓存日志单独出现也不确认完成。零变化包 transferred=total=0 时仍保留原值，不能因此确认差量网络传输；页面不显示该阶段的 100%、NaN 或 Infinity。

每次 download 开始清空旧模式、原因、进度、计划、缓存和校验证据；回退立即清空差量进度并重新采样完整下载进度。重复阶段/完成日志去重，失败后或完成后的迟到日志、进度和下载完成回调不能覆盖当前结果。dispose 关闭后也停止采集本次下载证据。检查刷新、显式下载、安装准备、保存确认与数据库关闭顺序保持原有行为。

## 2. 基础包集成

生产主进程始终提供 prepareDownload(updater) 钩子：先通过已校验 updater 配置的 getOrCreateDownloadHelper() 获取真实 helper.cacheDir，再调用 U01 的 prepareInstallerCache({cacheDirectory,appId,version})。不猜测 Electron cache 根，不扫描其他渠道目录。模块检查具体实现及 NSIS 行为由 U01 报告说明。

可信结果必须是 trusted === true。返回不可信或抛错时只对当前 download 设置 disableDifferentialDownload=true，并继续正常完整下载/完整缓存复用；下次再次验证，不能继承前次禁用。baselineReason 只接受 cache_missing、baseline_missing、baseline_invalid、identity_mismatch、version_mismatch、installer_missing、installer_unreadable、installer_corrupt、cache_changed、map_unusable、cache_invalid、unknown。未知内容映射 unknown。

createUpdateService 的默认钩子只保留既有依赖注入测试/独立调用兼容；生产 main.cjs 显式注入上述验证钩子，不走默认可信结果。

## 3. 上游证据与隐私

依赖精确锁定 electron-updater 6.8.11，未修改 node_modules。源码证据：

- AppUpdater.differentialDownloadInstaller：Download block maps 发生在读/下载索引及打开旧包之前；Full: / To download: 只是计划，不能解释成已传输或已节省。
- DifferentialDownloader：计划日志后才打开 installer.exe。仅用该计划边界区分索引请求和后续传输错误，不从格式化 KB 或计划比例推算任何字节。
- ProgressDifferentialDownloadCallbackTransform：COPY 不计入 transferred，total 为当前下载块字节，不是最后完整安装包大小。页面和 IPC 保留上游有效进度原值，不加本地复制量、不跨阶段累计、不计算节省率。诊断沿用既有整数投影。页面使用现有工作台的十进制 MB/KB/B 格式。
- DownloadedUpdateHelper：Update has already been downloaded to 日志在成功验证缓存后出现；还需匹配完成事件才确认缓存复用。无该日志的同进程快捷路径保持证据不足，不猜缓存命中。

fallbackReason 白名单：old_installer_missing、old_installer_unreadable、blockmap_failed、transfer_failed、checksum_failed、unknown。仅识别固定上游错误形状：旧包固定 basename 与 open/read 操作、索引为空/解析/版本/计划错误、HTTP/固定超时/Range/分段响应错误、上游差量校验告警。错误只取有界首行用于分类；栈中、地址中出现 ENOENT 或校验字样不能成为依据。无法证实的网络/存储错误归 unknown，不推断代理或 VPN。

原始 logger 字符串、URL、路径、Token、响应和错误栈均立即丢弃，诊断记录与重启读取/导出再经过字段白名单。新增事件仅 differential_downloading、differential_unavailable、download_cache_reused，保留既有 400 条/512 KiB 上限及原子写入方式。
