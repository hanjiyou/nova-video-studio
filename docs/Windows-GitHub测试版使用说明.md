# Nova Studio GitHub 更新测试版 A / B 使用说明

> 更新安装启动修复（待新版打包）：已为 GitHub 测试版及正式更新包恢复完成页默认勾选的“运行应用”选项，点击“完成”后启动。现有 3.6.5 不变，尚未进行真实安装验收。详见[修复记录](implementation/更新安装完成页启动修复.md)。

本说明适用于 A3.6.1 与 B3.6.2。两个版本都是用户批准的未签名测试版，Windows 可能显示“未知发布者”。安装包自带 Electron/Node、SQLite 和固定 FFmpeg，无需另装 Node/npm/Python/FFmpeg。本地构建和离线包核对不代表另一台电脑安装、真实 GitHub 下载、A→B 更新或资料保持已经通过，也不代表正式发布。

| 测试角色 | 版本 | 安装包文件名 |
| --- | --- | --- |
| A，原更新起点 | 3.6.1 | Nova-Studio-3.6.1-github-test-x64.exe |
| B，本次生命周期改造包 | 3.6.2 | Nova-Studio-3.6.2-github-test-x64.exe |

1. 将需要测试的安装包及该版本 SHA256SUMS.txt 复制到测试电脑，先核对 SHA256。实际安装与更新演练须在另行获准后执行。安装时选择当前用户可写目录；安装完成后从 Nova Studio GitHub Test 快捷方式手动启动。更新演练以已安装的 A 为起点，直接手动安装 B 只能证明手动安装，不能记作 A→B 更新通过。
2. 默认资料位于当前账户 %APPDATA%/Nova Studio GitHub Test；无需配置 NOVA_DATA_DIR，不要把资料放进安装目录。A/B 使用同一测试资料路径与应用身份 com.novaimage.studio.github-test。应用不会探测或迁移旧 nova-image 资料。每个资料目录只运行一个版本。
3. 首次进入可暂不配置连接；没有 Key 也能检查更新。设置应显示“GitHub 更新测试版 · 未签名”，当前版本应与所装安装包一致。每次应用启动只自动检查一次；无新包或网络失败不弹更新通知，可在设置手动重试。
4. A/B 均固定从公开 hanjiyou/nova-video-studio 的最新稳定 Release 读取 nova-test.yml。本轮仅制作本地包，没有创建 tag/Release 或上传资产；本地 B 存在不等于 A 已能在线发现 B。后续发布须单独授权，并提供 B 的完整 exe、对应 blockmap 与 nova-test.yml；不得上传测试 latest.yml。最新稳定 Release 若不带 nova-test.yml，测试检查会失败，不回退正式 latest.yml，也不自动查找更早测试 Release。
5. A 发现更高版本 B 后，由你点击下载；下载完成后再明确点击“重启并安装”。应用先确认草稿保存、任务与资料安全关闭。首次缺少旧安装器缓存时可能全量下载；完整性与 blockmap 校验保留，只有实际网络字节 / Range 证据足够时才能记录差分成功，不能承诺每次差分。
6. B 的任务控制默认图片 / 视频各同时处理 3 项，最长本地等待分别 120 / 300 秒；设置范围为并发 1–5、时限 30–1800 秒。时限从实际派发开始，排队另算；时限修改只影响新建任务。取消或超时只结束本地等待，远端可能继续生成或计费，不代表远端取消或退款。最近结果 / 任务中移除展示保留作品库和去重记录；活动任务先取消、确认结束后再移除。
7. B 首次打开 A 形态资料需要进行带备份的增量迁移。旧任务保留原 ID / 输入，不补造历史时限，也不自动重新生成；旧卡住任务会结束本地等待、保留远端待核对信息。未派发队列需明确继续。真实用户库迁移和 A→B 资料保持仍待安装态验收；本轮合成数据库回归不能替代这些结果。
8. 升级前自行备份整个测试资料目录及自定义输出。下载失败可继续使用 A 并重试；安装或启动失败保留包和记录，按提示重开或手动修复。卸载保留资料，安装目录会被移除；不支持 --delete-app-data，没有自动回滚保证。

NOVA_DATA_DIR 属于 override，只能检查 / 下载，不支持应用内重启安装，避免安装器重启后丢失环境变量。portable、unpacked、开发运行不支持自动更新。不要为测试关闭 Windows 安全设置。

本轮不读取真实 Key、不发起真实生成或付费调用、不安装 / 卸载本机 A/B、不创建 tag/Release、不上传、不 commit/push。正式签名 / 发布与许可材料、T15/M5/FFmpeg 完整对应源码、历史 NSIS 根因等状态不变。本测试包不能冒充完整功能或正式分发验收。


## 2026-10-26 下载体验 D04–D10 当前实现补充

已实现原任务内下载进度、重新下载、文件检查点、原来源恢复、HTTP/WS 版本同步和有界诊断，离线验收完成、源码与离线范围主审通过；未提交/打包/发布。详见[实施及验证记录](implementation/D04-D10-下载恢复与工作台体验.md)。本补充替代上文同主题“待开发”的旧阶段描述，原签名 URL 仅内存规则保持，历史证据保留。

新任务生成/下载独立预算：图片 120/30 秒、视频 300/180 秒；设置页各时限 30–1800 整数秒。下载排队不计时，刷新、多文件、校验与保存共用一次尝试截止；重试读取新配置，不重新生成。卡片/详情显示真实进度，未知总量不显示百分比，只有验证保存关联成功才完成。网络改善后点击“重新下载”，复用已验证完整文件，未保存文件从头下载，不宣称 Range 续传。

用户最终确认保持原来源存储规则，不新增恢复信息加密：安全持久源/内联资产/可原 ID 查询结果可跨重启恢复；无 ID 临时签名链接仅本次运行可用，重启或过期后无法恢复时明确提示，绝不重新生成。全部已验证检查点可恢复最终关联。task.revision 持久递增，HTTP/WS 与动作共享投影；requestId 重放回传 acceptedAttemptId 和当前状态。失败诊断保留实际字节、预算、原因和最近 10 次尝试；direct 不代表用户未启用代理。
