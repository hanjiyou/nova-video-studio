## 实现与身份边界

- 新增 `backend/connections/route-policy.js`，明确批准的传输源只有 `https://newapi.opensosen.cn` / `https://newapi.opensosen.com`，固定 `/v1` 基础路径。先校验原身份及合法端点/方法，再映射 models、图片生成/编辑、视频创建/查询/content。精确端口、路径、认证与禁止重定向重发约束保持；任意CDN、签名URL、其他供应商地址不映射。
- `getAuth()` 保持原来的不可变连接版本身份和原Key引用。线路按 `connection_id` 独立保存，切线不新增凭据版本、不要求重输Key；原Key清除后原任务仍失败，不借用新版本Key或新默认连接。
- 使用内置连接的原com身份与原能力ID，通过线路控件选择cn/com。此次不扩展“直接编辑Base URL为cn”的生成能力矩阵，也不将com真实生成证据复制成cn证据。原能力、参数、Preview和未实测例外闸门保持。
- 新增SQLite v11：`connection_routes`、任务生成传输快照列、下载尝试传输快照列及旧生命周期下载队列快照列。历史SQL和checksum原样保留；迁移仍先备份再事务。旧内置连接显式初始化cn，并清除旧线路check缓存，保留连接、任务、凭据、能力和用户模型设置。惰性初始化也先清除check再投影状态。
- 新生成在入队时由服务端冻结 `transportRoute`；客户端不可提交该字段。相同localRequestId重放比较用户意图，排除服务端补充线路字段，因此切线后仍返回原任务。旧未派发任务首次派发前在追加列固定线路，不改历史不可变输入快照。
- 每次正常查询读取原任务所属连接的当前线路，保持原ID、原版本Key。生成已在途的响应继续归原任务处理；旧线路生成的型号拒绝，不能刷新或触发新线路的退避。
- 下载入队冻结本次尝试线路；多文件、临时来源刷新、重定向与重新进入worker都共用该快照。下一次手动“重新下载”才读取新线路。旧生命周期预算规则保持。inline/已导入资产继续本地验证保存。
- 受管视频content来源按原身份存储，只在实际请求时选线。离开精确批准下载目标后去除Key，跳回也不恢复。无自动fallback、无POST重发、无Range续传或恢复加密新增。
- 模型成功缓存、失败退避、在途合并与候选验证按连接版本及route/revision隔离。切线清除可见性缓存，迟到成功/失败不覆盖当前线路。候选验证也检查原版本及当前线路修订；仅验证通过再原子保存。
- 任务HTTP/WS/历史共用的投影新增线路快照；诊断仅允许cn/com、正整数修订、两个白名单host和固定operation，不包含Key、完整URL、查询串或任意host。

## 接口交接

连接summary及models：

```ts
routeSupported: boolean
route: 'cn' | 'com' | null
routeRevision: number | null
```

新内置连接和升级后的旧内置连接默认 `cn / 1`；自定义地址返回false/null/null。models还提供 `transportEvidence: 'generation_unverified' | 'see_capability_evidence'`，不能把后者理解为所有com组合已经实测。

现有 `saveConnection` / `validateAndSaveConnection` IPC请求可增加 `route` 及 `expectedRouteRevision`。已有连接明确提交route时必须携带读取到的修订；冲突返回 `CONNECTION_ROUTE_CONFLICT`（409）。旧请求省略route时保留当前线路，继续使用现有expectedVersionId控制连接身份。仅切线路可复用connectionVersionId，任意Base URL变化仍要求新Key。

`POST /api/nova/connections/:id/check` 可携带 `expectedRouteRevision`；省略则检查当前线路，携带旧值返回409。其余现有受保护HTTP/IPC边界不新增保存端口或任意host接口。

任务DTO与 `downloadAttempt` 新增：

```ts
transportRoute: { route: 'cn' | 'com'; revision: number } | null
```

任务字段表示生成冻结线路，downloadAttempt字段表示该次下载冻结线路。旧已派发历史缺值保留null，含义为“未记录”，不可倒推为cn。`getAuth`原字段不变；内部连接服务另提供 `getTransportRoute(connectionVersionId)`。
