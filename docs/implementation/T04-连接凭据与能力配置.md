## 主会话审查追加：编码错误回显

主会话指出图片失败路径只对原始Key使用replaceAll。先保留生产代码不变，使用每个UTF-8字节都写成%HH的一次、两次编码响应进行真实HTTP复现；[原始复现](t04-evidence/encoded-error-reproduction.log)中4项桌面场景失败、2项Web对照通过。一次/两次编码及其非法百分号前缀场景均在任务HTTP、已订阅WebSocket、SQLite tasks.error和task_items.error中发现可恢复Key。该次复现的storage历史DTO、事件和进程日志没有观察到泄漏，未把这些通道写成已复现泄漏。

桌面credentialSafeError现使用共享containsCredential检查完整错误，再进入normalizeError截断；命中后整个上游详情替换为固定的“上游错误包含连接凭据，已隐藏详情。”。共享检测检查原文并最多进行两轮百分号字节解码，支持全字节、混合及Unicode编码；无关的%ZZ或非法UTF-8字节不再让整个检测提前结束。插件和资源URL继续复用该检测。Web分支仍返回原错误，真实HTTP对照确认一次、两次编码的旧错误文本保持原行为。

[修复后回归](t04-evidence/encoded-error-regression.log)6/6通过，4项桌面场景逐一确认HTTP、WS、tasks/task_items、事件、storage历史与日志中没有原始或发送过的编码Key；另加1项共享检测回归。最终针对性75/75、后端217/217、lint通过。前端源未在此次安全修复中变化，保留此前682项及生产构建证据，没有重复声称本次重跑前端全套。
