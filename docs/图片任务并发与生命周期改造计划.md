## 1. 这次要解决什么

图片或视频请求卡住时，不应阻塞同类其他任务或另一类任务。用户可以同时生成图片和视频；每个已开始的任务有最长等待时间，可以取消；不想看的任务记录可以移除，已有作品保留。诊断应能解释时间花在请求、接收还是保存上。

此次覆盖已有图片及视频模式（文生视频、单图、多图），不扩展模型能力或改变已核实的生成请求参数。视频新增同样的并发、总时限、取消、移除和诊断规则。保留视频有界状态查询重试，不增加自动重新生成、代理设置、批量删除或新的远端取消服务。

### 已查到的事实与未确定的原因

- 现有 service.js 的 pump 同时受全局占位和等待整个 submit 返回约束；不是修改一个并发数字就能解决。
- 图片适配器目前有 30 分钟超时；下载还有独立超时，二者不是用户要求的整任务 120 秒。
- 最近一次诊断中，23:19 图片任务已派发但结果未知，后两项尚未派发且需继续。单个未知任务占住全局生成名额。
- 同步图片接口可以直接返回图片或 URL，没有远端任务 ID 本身不是故障，也不能编造 ID 来轮询。
- 现有移除逻辑隐藏任务，查询同时服务作品库；直接复用会导致作品从库中消失。
- 现有诊断只有任务起止时间和事件数量，不能证明慢在模型、网络还是本地保存。VPN/TUN 影响是线索，尚非根因结论。

本计划按症状修复调度和控制能力，不承诺能修复中转或网络本身。

## 2. 产品规则

| 项目 | 本次规则 |
| --- | --- |
| 图片同时处理数 | 建议默认 3，可配置 1–5；这是本计划的实现默认值，不是模型服务能力承诺。范围集中定义，后续有依据再调整。 |
| 视频同时处理数 | 同样建议默认 3，可配置 1–5，与图片独立设置；非用户指定的硬性数值。默认最多 3 个图片加 3 个视频本地任务，不保证中转接受此并发。 |
| 名额覆盖范围 | 从实际派发到媒体验证、保存完成，包括视频远端排队、生成、轮询间隔和等待下载；两类分别计数，互不占用名额，不只统计 POST 请求。 |
| 排队 | 名额满时才排队；有空位立即按可执行队列先后补位。重启后需要用户继续的任务不自动派发。 |
| 超时 | 图片默认 120 秒，视频默认 300 秒；分别配置，建议范围均为 30–1800 秒。任务创建时保存对应配置快照，实际派发时开始计时；本地排队时间另算，远端排队计入。 |
| 时间范围 | 一份总预算覆盖上传参考图、提交、响应体接收、解析、视频远端排队/生成与轮询、结果下载、验证及保存，阶段切换不重置预算。 |
| 修改设置 | 时限只影响新建任务；并发上限立即影响后续入场。降低上限不取消已运行任务，等数量降到上限以下再派发。 |
| 取消 | 排队项直接取消；已派发项停止本地等待与处理，进入“已取消”。不宣称中转已取消或退费。 |
| 超时结果 | 显示“超时失败”，停止本地等待，不自动重新生成。可能到达中转的请求保留“远端结果待核对”。 |
| 移除 | 最近图片/视频结果和任务列表移除的是同一任务记录的展示，作品库文件与作品条目保留；不物理删除任务和去重凭据。 |
| 进行中移除 | 首版采用“先取消，再移除”两个明确动作，不增加复杂批量操作。 |
| 手动再试 | 生成新的图片或视频是新的明确操作；不会在超时、取消、重启或更新后自动发新 POST。下载重试只能重取已有结果。 |

图片 120 秒、视频 300 秒是默认本地等待上限，不是服务一定能在该时间内完成的承诺。请求可能已在中转执行，取消或超时不代表远端资源立刻释放；本地释放名额可能让远端同时存在更多任务，界面用一条清楚提示说明即可。

## 3. 生命周期与数据边界

### 本地结束和远端结果分开记录

本地可显示：排队中 → 提交中/接收中/远端排队或生成中/下载中/保存中 → 完成、失败、超时失败或已取消。
“提交中”等阶段是可观察的本地阶段，不把等待 HTTP 响应伪装成已知模型生成进度，不显示虚构百分比。

远端记录独立保留：未派发、已确认结果、已确认拒绝、结果待核对，以及确实收到的远端 ID。本地结束不能把未知远端结果改成失败或已取消。

- 完成、取消、超时争抢同一个终态写入权，只有一个胜出。
- 所有异步回调在保存、资产绑定和状态更新前核对执行标识与当前终态。迟到响应不能把取消/超时改成完成。
- 一旦本地截止，停止可中止的网络及下载；只清理此任务临时文件，不删除共享文件或已有作品。
- 本地逻辑名额与尚未退出的请求/文件操作分别跟踪。取消后不得留下无人管理的写入；不能安全停止的少量本地收尾必须被追踪，禁止积累无限后台操作。
- 更新安装仍须等待真实 IO 与数据库操作安全结束。不能因为界面写了“取消”就允许强行更新退出。
- 单个事件循环内的同步解析/文件操作可能阻止定时器执行。大块处理需可中止或分段；至少在下一检查点拒绝超时完成，不承诺硬实时毫秒级中断。
- 单次执行用单调计时；持久化派发时间、截止时间和时限快照供重启恢复。跨重启不赠送新的完整 120/300 秒，时钟异常保守处理并记录。

### 视频轮询与停止的具体规则

- 收到真实远端 ID 后，各视频独立调度查询，不因另一个任务的请求或轮询阻塞。每任务最多一个在途状态查询；查询间隔、有界退避及服务限流处理保留，绝不以并发为由高频轮询。
- 300 秒从首次实际派发起算，包含上传、远端等待及轮询退避。既有轮询预算不能让总时限延长；请求超时与下一次查询等待取剩余预算，截止时停止计时器和在途查询。
- “停止查询”与“取消任务”分开：前者不表示远端取消，也不重置截止时间；暂停查询仍由截止计时器管理，到期本地超时并释放名额。要立即释放名额可取消本地任务。恢复查询只允许未本地结束且未过期的任务，并查询同一个远端 ID。
- 取消或超时保留远端 ID 和结果待核对信息，自动查询停止。迟到成功不得覆盖本地终态；本轮不另增终态后自动取回功能。
- 查询失败的有界重试仅重复查询，不提交新的生成 POST。无远端 ID 的视频不能盲目查询或重发。中转明确拒绝并发时准确报错，不无限等待或绕过限流。

### 旧任务和升级

旧记录无新配置快照，不能修改原不可变输入来补造“当时已设置 120/300 秒”。

- 未派发排队项保留，重启后继续需要用户操作；不批量静默提交。
- 已派发、无 ID、结果未知的旧图片或视频任务解除无限占位，显示结果待核对，允许本地取消和移除；不制造轮询接口，不重发原请求。
- 旧活跃任务在升级启动时做一次有记录的本地恢复处理：结束旧本地等待、保留远端不确定性，不冒充已由远端确认失败，也不标成原本有 120/300 秒时限。
- 旧视频有远端 ID 的保留该 ID；本轮升级恢复结束旧本地等待并释放名额，明确告知远端可能继续，不自动重发或静默重启轮询。与旧无 ID 任务一样，不补造过去的截止时间。
- 新视频有 ID 且未过期时保留可恢复查询能力，按原恢复约定由用户继续同一任务，只使用剩余预算；已取消/超时不可通过恢复查询复活。
- 新任务如果重启时已过截止时间，恢复为超时；未过期也不得重发生成请求。能恢复的结果下载仅使用剩余预算和已保存有效来源。
- 带签名结果地址可能只在内存中；重启后丢失不能伪造可恢复能力。
- 手动下载重试采用独立明确的下载尝试和预算，保留原生成尝试耗时，不覆盖旧超时结论，不发生成 POST。
- 新字段使用现有带备份、校验和事务的增量迁移。不得更改旧迁移校验和；旧输入快照、目录版本和去重 ID 保留。
