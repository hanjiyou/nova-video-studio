## 1. 已确认的方向

用户要求优先还原 OpenChatCut 原版，避免自行重组界面或扩展功能。Nova 新增左侧“视频剪辑”入口，点击进入真实原版编辑工作区；工程列表沿用原版打开/管理流程，不将作品卡片首页充当剪辑界面。

原版固定为 fork `https://github.com/hanjiyou/OpenChatCut.git`，子模块 `third_party/openchatcut`，基线提交 `7fa4b7903e7ebecf832a36249f0c0c755200cc17`。Nova 当前交付基线为 3.6.10 源码 `69c432d`、文档 `e8e9480`；根 package.version 不是安装包版本。

设计依据：[原版接入范围](design/openchatcut-integration-native-v2/design-scope.json)、[剪辑工作区](design/openchatcut-integration-native-v2/01-native-editor.png)、[资源库](design/openchatcut-integration-native-v2/02-native-resource-library.png)、[导出回库](design/openchatcut-integration-native-v2/03-native-export-return.png)。此前 `openchatcut-integration-20261031-v1` 中自定义九页签和工程卡片主界面已被替代。设计图是示例，不是运行验收证据。

首批授权记录：需求分析、文档同步、子代理开发、必要依赖安装、隔离本地验证；随后用户另要求本地打包及FFmpeg去重，已按相应本地范围完成。当前后续融合暂缓；没有提交推送、安装覆盖、发布或真实付费服务调用授权。

## 3. 技术路线与已核对事实

- 采用独立 session 的 Electron WebContentsView 承载原版界面，保留 Nova 左侧导航；iframe/webview 不作为方案。宿主和侧服务生命周期由 Nova 管理。
- Nova 主页面现有 `worker-src 'none'; frame-src 'none'`、主 frame token 和 IPC 来源检查保持。新 View 是独立 webContents，不能获得 Nova 会话令牌或完整 novaDesktop API。
- 原版服务单独进程、单独 profile/cwd，复用共享服务装配。不得直接 import 原版 desktop/main.ts（带 app 生命周期、单例锁和全局副作用）。
- 首轮运行探针采用原版浏览器 HTTP 存储模式，不暴露半套 `openChatCutDesktop`；原生转写等窄桥随后逐项适配，不暗示已全部可用。
- 本机 Node24.14.0；Nova 已装 Electron43.4.0 的 Node24.18.1 支持 node:sqlite。原版声明 Electron^43.8.3，仍需实际构建与运行验证。
- 原版 profile 在模块导入时冻结，必须在进程初始化前指定 Nova 独立数据目录；不得读取开发者现有 ~/.openchatcut、.env.local、真实用户库或凭据。
- 原版 keystore 会写文本配置，必须在正式允许配置凭据之前提供宿主持久化适配。首批离线探针不继承真实服务密钥，不测试付费网络。
- 原版 CLI 写入会取得工程所有权，已打开工程不能另用离线CLI并发修改；素材桥接需走当前编辑上下文或原版受控入口。
- 当前 Nova 库只查询 tasks.saved_at + task_assets(output)。编辑回库需独立本地作品记录及查询适配，不能只 importFile 或伪造任务。
- 100MiB、全文件读内存和时长/校验预算遍及导入、下载、预览和另存；只调大常量不是合格的大成片方案。
- 独立本地预览流程已收集固定原版构建产物与生产依赖，local.1/local.2均已生成；正式交付仍未完成子模块初始化、完整资源/许可证和安装升级接线，不将本地预览流程当作正式分发完成。

## 5. 首批历史责任与完成门槛

- 构建子代理负责 `config/openchatcut-runtime.json`、`scripts/openchatcut*.cjs`（含探针/服务入口/构建）、根 package.json 中限定脚本及相应测试；独立安装子模块依赖不改原版锁文件。
- 宿主子代理负责 `desktop/openchatcut/**`、`desktop/main.cjs`、`desktop/ipc.cjs`、`desktop/preload.cjs` 及对应后端隔离测试；不改 Nova 原 session-policy，不触碰 credential-vault.cjs 的既有未提交修改。
- 入口子代理负责 `frontend/src/components/workbench/WorkbenchShell.tsx`、新增 WorkbenchEditor、前端窄客户端/类型及测试，和 backend workspace 设置中 editor 页面枚举及相关测试；不修改宿主/构建文件。
- 主代理维护计划、契约、总台账，审核跨层行为，独立复跑有关测试，记录失败与未覆盖项。
- 首批必须交付可复现启动入口和真实缺项状态、宿主离线边界测试、导航回归与完整前端类型检查。依赖安装和原版运行结果如实记录；真实媒体保存/渲染未验证不得称链路完成。
- 后续需验收初次进入直接打开原版编辑上下文、已有工程恢复；原版工程列表只能作为原版管理入口。首次运行探针若只能显示原版壳/首页，必须登记为局部验证。
