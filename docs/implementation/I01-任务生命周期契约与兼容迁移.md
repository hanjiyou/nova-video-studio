5. 仅迁移不创建任务服务、不触发适配器；专项将 fetch 替换为拒绝函数并断言调用 0 次。所有生成/查询测试均为内存函数替身，未启动 HTTP 服务。
6. 新任务排队时 attempt/deadline 均为 null；假时钟先等待 60 秒，派发后 deadline 恰为派发时间+原创建快照 120 秒，设置改成 90 秒不影响该任务。新视频读到更新后的 450 秒快照。attempt/deadline 重写被数据库拒绝，重传/重开不重置。

## I01 完成时的历史边界与交接（当前 I02–I04 已通过）

- I02：图片/视频各自并发入场、完整流程占位与公平下载未启用。当前 pump 仍唯一占位并等待 submit 返回；设置保存不代表运行并发改变。
- I03：整任务 deadline 中止、单调计时、执行中取消、原子终态胜出、迟到响应/下载/保存 fence、真实 IO/清理跟踪未启用。当前 status 集合也未新增运行中的 timed_out/cancelled 路径；新增 localOutcome 字段是独立数据契约。
- 派发边界的 attempt/deadline 已在数据库，但当前 chosen.submit 收到的 task 仍是派发 update 前的旧 row。I03 接适配器前必须重新读取 row，或显式传递同一不可变执行上下文，不能只读取旧参数对象来推断时限。
- execution_attempt_id 与 execution_deadline_at 属原生成边界且不可变。download_failed 投影为本地 failed、无生成占位；本批保留原 retry-download 行为。I03 必须新增独立下载尝试字段/表与预算，保留原生成耗时及取消/超时结论，不能覆盖生成边界，也不能重新 POST。
- 当前 background 的任意 rejection 会 closed=true 并 abort 全部请求。I02/I03 必须区分单任务取消、超时、预期终态竞争与真正存储故障，避免一项取消关闭全队列。
- I04：旧活动任务一次性恢复、跨重启剩余预算、暂停/恢复查询截止、更新关闭安全收尾未实施。旧行无时限并不说明恢复已解除占位；迁移不改旧状态，不重发 POST。
- I05：workbench_removed_tasks 仅建立独立展示范围，尚未接入口或过滤；原 workbench_hidden_tasks 和作品库行为保持。新移除入口不得删除任务/去重/作品，也不得恢复旧隐藏记录。
- I06/I07：阶段采集/有界安全诊断和新设置/任务交互未实施；phase/phaseStartedAt 仅预留，未知为 null，不填造耗时或百分比。
