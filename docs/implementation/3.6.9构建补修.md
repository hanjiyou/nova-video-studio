## 失败原因

electron-builder 26.15.3 的 `computeCommonInstallerScriptHeader()` 先包含 StdUtils，再注入 `nsis.include` 指定的业务文件；`installer.nsi` 的常规辅助头文件随后才加载。`update-cache-installer.nsh` 在顶层定义 `.onGUIEnd` 与 `.onInstFailed`，当场展开 `novaCloseInstallerCache`，此时 `${If}` 所属的 LogicLib 尚未引入，编译器因此报告 `Invalid command: "${If}"`，定位到业务 include 第 20 行。

原缓存专项 harness 在业务 include 之前预加载 LogicLib/FileFunc，隔离测试通过而首次完整集成失败。前端构建和应用打包阶段已通过，不能据此宣布 NSIS 包构建成功。

## 最小修复与回归

- [update-cache.nsh](../../desktop/installer/update-cache.nsh) 显式 include `LogicLib.nsh`，使回调在展开缓存宏前已具备依赖。LogicLib 自带重复 include 保护；缓存行为及渠道身份规则不变。
- [windows-update-cache-harness.cjs](../../scripts/lib/windows-update-cache-harness.cjs) 保留 builder 原有的 StdUtils 前置顺序，把 LogicLib/FileFunc 移至业务 include 之后，并在业务 include 前用预处理断言拒绝已加载的 LogicLib，防止测试再次掩盖依赖顺序。安装器与 BUILD_UNINSTALLER 两种现有真实编译路径都采用该顺序。
- 未修改 node_modules、发布策略、版本配置或资料保留逻辑；现有 `desktop/credential-vault.cjs` 及其他工作区内容均保留。
