## 实现范围

沿用 B3 深色紫色四页、四个 SQLite 草稿、配置和凭据边界。图片页按参考图是否存在决定 image.text/image.reference；视频三模式分别恢复草稿，切换不裁图。导入仍复制原 PNG/JPEG；卡片拖动、前移/后移、数据库 position 与实际 multipart 使用同一顺序。

工作台接入真实本地创建、状态、最近任务、快照详情、图片等比预览和放大、媒体 controls 播放、assetId 另存及定位。无供应商进度时只显示状态与实际已用时间，不生成模拟百分比。另存取消作为正常本地结果，生成/下载失败与另存失败分开。

作品库提供图片/视频分类、提示词或模型关键词、状态筛选、24 条分页、准确 total、无结果/空库区分、详情、按选择顺序跨页选一或两张 PNG/JPEG 带入视频。复用任务快照保留型号、原提示词、历史参数及有序输入；确认替换目标草稿后仍需明确点击生成，不自动发请求。缺失输入保留提示并阻止提交。输出目录只显示受控根名称、文件名和目录版本，真实路径仍由宿主解析定位。

## 持久提交意图与去重

schema v6 为追加迁移，v1–v5 SQL/checksum 不改，沿用升级前 SQLite 一致备份/回滚。新增表只保存窄边界输入与本地提醒，没有第二套调度器。

1. UI 固定 localRequestId、原连接/能力、提示词、参数、有序 assetId。
2. POST `/api/nova/storage/submissions` 经同一输入/能力/素材预检，冻结当前输出目录，持久保存并返回实际将发送的输入。
3. POST `/api/nova/storage/submissions/:localRequestId/attempt` 持久标记进入发送步骤；重复标记拒绝。
4. UI 仅一次调用既有 `/api/nova/workbench/tasks`。已保存意图与创建 body 必须完全相同。任务服务仍负责原子入队、持久 localRequestId 去重和全部派发/查询/下载。
5. 回执异常只 GET 本地意图，通过 localRequestId 关联已持久任务，不重发创建。不明意图重启保留；尚未进入发送步骤与已进入发送步骤分别说明。读本地核对失败会暂停新创建并提供重读。
6. 同一未改草稿提交后保持禁用；需要明确“准备以相同草稿新建任务”后再点击生成。结束未明意图核对有独立风险确认，不取消远端、不释放任务占位，也不自动新建。

所有状态读取均为本地 HTTP/SQLite，不触发上游 GET/POST。Key、密文、原 URL 和原始响应不进入意图、草稿或 DTO。

## 任务动作与文件保留

详情接现有取消未派发队列、重启明确继续、停止查询、同一 ID 恢复、人工核对后补 ID、重试下载。已派发 submission_unknown/polling_paused 保留单生成占位，后续队列等待明确终态；界面说明远端可能继续生成/计费，停止查询不等于取消或退款。

completed 输出被外部移除时，允许用户明确重新进入原任务下载队列。只复用原结果源/同 ID 只读刷新，不重新生成、不换 Key/目录。仅这一经过缺失文件核对的下载动作可从 completed 转回 remote_completed；完整解码与受管发布完成后才再次 completed。

移除记录采用隐藏标记，保持原任务、localRequestId 唯一性和去重事实，默认不删文件。非明确终态（包括提交不明、暂停、下载未完成）禁止移除。单独勾选“同时删除独占生成输出”后，在 SQLite immediate 事务内再次核对全部任务/输入/草稿、待提交意图、下载候选及旧受管别名；仅独占 generated 输出可清理。删除前核对真实路径和摘要。输入、共享输出、用户导入源文件均保留。文件失败明确计为保留/失败，不误报已删文件。

## 主审修复：跨资产 ID 的物理文件别名

2026-10-24，主会话独立复现：重复选择同一输出目录会产生不同 root_ref/assetId，但相同受管键落在同一实体路径。最初删除只按 assetId 查引用，会误删另一任务使用的实体文件。首次审查因此暂不批准提交；该问题已在同一代理修复，并经后续主审复审接受。

删除现在在既有 SQLite immediate 事务内解析全部现存受管资产的可信 realpath，以规范路径归并对象（Windows 保守忽略路径大小写），不依赖 root_ref、assetId 或仅内容摘要判同。对同一实体的全部资产记录检查其他任务输出、全部输入、草稿、下载候选、提交意图及旧受管别名；任一引用或非 generated 来源均保留文件。解析不安全则明确保留并返回文件错误。独占对象通过摘要及最终路径复查后才 unlink，全部别名统一标 missing，同一实体只计一次；已经缺失的文件不计为成功删除。没有改动目录版本、导入身份或旧数据库记录来掩盖问题。

新增 [物理别名回归](../../backend/test/workbench-b4-physical-aliases.test.js) 保留不同 assetId，且重建 store 后再删除，覆盖同目录重选、默认根后显式重选同目录的六类引用，以及同任务输入、独占别名只删除一次、不同实体目录中的相同字节仍可独立清理。修复前 15 项为 **1 通过/14 失败**；修复后新增 15 项与原 B4 9 项合计 **24/24 通过、0 跳过**。受影响文件 lint 通过，详见 [修复证据](b4-evidence/physical-alias-review.json)。原先 123 项后端/30 项前端/31 项 Electron 是本批首次交付的历史运行结果；本次按影响仅重跑这 24 项和 scoped lint，没有重跑无关前端、构建、原生或全量验收。主会话随后独立复审通过，明确批准记录审核后提交推送 origin/dev，见[主审记录](b4-evidence/approval-review.json)。
