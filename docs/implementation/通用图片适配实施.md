# 通用图片适配实施

日期：2026-10-28。状态：M02代码和离线回归已完成，待主会话集成审核；未提交、推送、打包或发布。

## 本轮行为

本轮依据用户明确授权启用sunburst。图片型号由集中配置选择同一套已经实现的标准图片协议；flare与sunburst均可由用户主动提交文生图或单张原图参考，自动模式的空参数对象也可提交。请求中的model始终来自任务冻结快照，不再由适配器写成flare。

这表示客户端按用户配置开放提交，不表示中转服务真实生成已经验收。新能力记录始终为unverified、applicationVerified=false、sourceIds=[]；不复制flare最小文生图的真实成功证据给sunburst、编辑或附加参数。

需求与界面总体方案见[模型显示配置与通用图片接入计划](../模型显示配置与通用图片接入计划.md)。

## 配置与协议边界

集中入口为backend/tasks/image-policy.json：

- models按完整精确型号登记profile、submissionEnabled；当前登记gpt-image-2.5-flare、gpt-image-2.5-sunburst，均为true。
- profiles.openai-images-v1声明文生图与单图参考模式，以及尺寸、质量枚举。型号可通过modes、sizes、qualities缩小或显式调整自己的已确认配置。
- 顶层model/sizes/qualities保留为旧flare能力的兼容定义；新增型号应写入models，不修改这些历史字段冒充新型号。
- imageRule(model,scope)只接受已在代码实现的openai-images-v1协议、opensosen供应商、精确canonical baseUrl=https://newapi.opensosen.com/v1及openai连接协议。scope支持baseUrl或数据库base_url。
- 同协议新型号只需新增精确models配置；未知型号、未知profile、未知模式均拒绝。更换协议、接口字段或结果结构需要新增实现和测试，不能仅凭“OpenAI兼容”或目录可见性自动接入。
- 改变已有参数定义或能力语义须追加能力版本并保留旧版本兼容；不重写已登记能力或历史任务快照。

文生图使用POST /v1/images/generations，JSON为model、原prompt、n=1及显式选择的size/quality。空参数时不发送size/quality，也不额外发送auto、流式开关或其他未配置字段。

单图参考使用POST /v1/images/edits，宿主构造multipart，字段model、原prompt、n=1、可选size/quality，以及唯一image文件部分。文件只接受受管原PNG/JPEG，仍核对有序素材、真实字节与MIME；FormData生成boundary，不裁图、压缩或转码。

## 新任务、历史任务与证据

保留opensosen-flare-image适配器身份及1.1.0版本。1.0.0仍只允许旧flare最小文生快照；不把历史任务升级或改绑。文件名、工厂名和MODEL旧导出保留用于历史兼容，实际请求从snapshot.model读取。

新增能力版本为opensosen-configured-images-2026-10-28-v1，明确记录submissionPolicy=explicit-user-configured-image-protocol-v1、configuredProtocol=openai-images-v1、submissionEnabled=true。按配置对每个支持型号和模式幂等追加独立能力，现存行与UUID不变。

旧opensosen-image-controls-unverified-2026-10-24-v1及原最小文生图能力继续保留。flare最小文生图仍优先显示原application_verified能力；同一未验证模式的新配置能力优先于旧控制能力。新版本允许空参数，旧控制版本不被改写成新的自动模式授权。

新工作台任务的检查顺序为：

1. 验证输入，按原adapter版本兼容历史快照，查找已有localRequestId。
2. 只有新意图才确认模型目录；等待期间再次排重。
3. assertModelDisplay检查当前显示选择，随后检查目录可见性。
4. allowsNewSubmission检查精确图片配置的submissionEnabled、模式、参数及连接范围，再验证受管素材与冻结能力。
5. 正常入队，继续原来的单次提交、结果验证及保存流程。

后来隐藏型号时，新ID返回MODEL_HIDDEN；相同ID返回原任务。当前配置关闭submissionEnabled时阻止新意图，但已有冻结能力的执行校验不依赖当前显示/开放开关，历史队列仍可明确继续。旧图片入口对所有注册图片型号统一要求标准工作台接口，不能绕过能力版本。

## 传输与结果

继续复用原cn/com线路策略：身份、凭据版本与能力仍绑定原canonical服务，新生成按入队冻结线路发送；只映射两个精确内置HTTPS源的受管端点。不把com历史成功当作cn真实生成证据，不让CDN或任意自定义地址继承鉴权。

适配器每次submit只执行一次POST。拒绝、断连、空结果、JSON解析失败和超时均不自动重发，不自动换型号或参数。URL与base64结果进入原媒体验证与保存链路；图片返回URL的authScope保持none，不携带生成Key下载。凭据回显、坏图片与错误MIME继续拒绝。
