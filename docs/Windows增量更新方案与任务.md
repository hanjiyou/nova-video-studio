## 1. 推荐路线与范围

首期采用 **Windows x64 NSIS + electron-updater + GitHub Releases**：每次启动后后台自动检查一次，同时保留手动检查入口；用户主动下载，下载完成后明确点击“重启并安装”。增量指尽量复用旧安装器缓存、按 blockmap 差分下载，最后仍校验并执行完整 NSIS 安装器；不是直接修改正在运行的应用文件。

启动检查在已安装应用的主实例就绪后发起，不阻塞工作台；每次应用进程启动只触发一次，不因页面切换、窗口重开或第二实例唤醒再次触发，不设置定时轮询。自动检查失败安静结束，本次启动不自动重试；用户仍可手动检查。发现新版用可关闭的轻量提示，同一次启动同一版本不重复自动提示；无新版不提示。默认不自动下载，不在普通退出时自动安装，不静默强退。差分不可用时允许库的原生全量回退，显示实际已知状态和原因，不承诺每次都是增量、固定节省比例或每次回退前再次询问。若后续要求“绝不全量下载”，先对锁定版本做技术查证，再单独调整范围。

首期不做自研 patch、热替换、自动回滚、跨平台、多渠道切换或 CDN 改造。构建与发布分离，现有本地 `3.4.0.n` 测试包流程继续保留。

## 3. 版本、安装身份与分发物

正式更新版本应统一，例如：

| 字段 | 旧版示例 | 新版示例 |
| --- | --- | --- |
| package / app.getVersion() | 3.5.0 | 3.5.1 |
| Git tag / Release | v3.5.0 | v3.5.1 |
| latest.yml 的 version | 3.5.0 | 3.5.1 |
| Windows buildVersion | 3.5.0.0 | 3.5.1.0 |

示例不授权现在改版本。U01 冻结规范化方式、最低支持版本、签名和唯一更新源；不覆盖同号 Release、安装器或清单。旧应用没有更新模块，须先手动安装含模块的 bootstrap 版本，后续才可应用内更新。测试身份到正式身份的资料迁移另行设计，首期不自动探测、搬运旧资料。

每个支持更新的版本至少保留 builder 生成的完整 `.exe`、配套 `.exe.blockmap` 和 `latest.yml`。清单包含 version、文件路径/大小、SHA512 等库所需字段，必须由锁定工具生成并校验，不能手写伪造；当前 `.sha256` 与 `build-summary.json` 仅用于本地核对，不能替代更新清单或 blockmap。

更新源固定绑定经授权的 owner/repo、安装身份和发布规则，渲染器不能指定任意 URL、安装器路径或 feed。客户端不携带 GitHub 发布 Token。可建议独立、公开的 releases-only 仓库便于匿名下载，但创建仓库、改变可见性、选择现有仓库为 feed 都须另行明确授权；私有分发的鉴权不能靠把发布端 PAT 塞入应用解决。

需按最低支持版本范围保留旧版安装器与 blockmap；本地旧安装器缓存可能缺失、被清理或不匹配。GitHub 普通 provider 可以分多次单 Range 请求取片段，不要求服务支持一次请求内多个 Range。需要实测重定向后的下载来源、HTTP 206 / Content-Range、实际网络字节和最终文件完整性。清单哈希校验与发布者签名验证各自负责不同问题，不能互相代替。

## 4. 安装门闩与恢复原则

检查、下载更新不自动中断生成。点击“重启并安装”后先进入安装准备：

1. 原子阻止新任务提交和队列继续派发，同时检查主进程/后端活动；有未结束的创建请求、素材导入/导出或媒体落盘时暂缓，提示用户等待，不能为赶安装中断或重发创建。
2. 确认四种草稿、设置和本地提交意图已保存成功；保存失败或回执无法确认时不安装。不能仅凭渲染器自报“空闲”绕过后端核对。
3. 对已持久化的远端任务安全停止查询，保留原连接版本、上游 ID、不可变快照和生成占位。submission_unknown / polling_paused 记录本身不等同仍在执行的本地 POST；待确认本地无活动写入且记录完整后，可提醒远端可能继续生成/计费，由用户明确重启，不强行将状态改成完成或取消。
4. 等待媒体文件原子落盘或可证明的恢复点，完成数据库 checkpoint/关闭与资源清理；处理现 before-quit / app.exit 钩子，使用锁定 updater 的正确安装退出契约，避免重入、直接退出跳过安装或普通退出误触安装。
5. 门闩失败/超时则保留已下载包和记录，提示稍后重试；可安全解除准备状态时恢复正常使用，不自动强退。新版本启动按现有恢复规则，有 ID 只查同一任务，无 ID 且已派发不自动 POST。

资料目录、媒体和凭据保护必须保持。本期无 schema 改动，不新增全面备份系统；如将来涉及 schema 迁移，先明确备份与兼容恢复方案。下载失败时旧版继续使用；安装异常保留资料与可用备份，通过受支持的手动恢复或更高版本修复。schema 改变后不承诺自动降级或自动回滚。
