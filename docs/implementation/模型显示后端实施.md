当前为源码实现与离线验证范围，未提交、推送、打包、安装、发布或真实生成；未读取真实用户数据库与凭据。

## 实现

`backend/connections/service.js` 使用既有 app_settings 保存每个连接凭据身份的显示列表、默认模型与价格分组，不新增 SQLite 迁移。初始 revision=0 持久化冻结，后续清单刷新只更新供应商可见性及已知型号，不替换用户选择。PUT 事务核对连接版本、线路 revision 和显示 revision，完整保存一组设置；型号分类、默认上游可见及协议可提交条件由后端验证。

models/model-display 返回完整设置及实际协议配置推导的 submissionEnabled。手工分类与勾选不新增能力；Preview 仍禁用。隐藏仅由首次任务创建入口校验，旧任务排重及执行恢复不读取当前显示策略。新草稿 HTTP 投影只补未保存空草稿的有效默认，已有草稿保持；旧向导默认保存与新显示默认在一个事务内同步，冲突明确返回；允许 null 明确不设置缺少可用型号的媒体类别，仅图片及自定义连接可完成向导。

`backend/connections/image-pricing.js` 改为缓存匿名公开定价快照，按请求兼容图片型号及用户明确选择的精确分组计算基础价×倍率。两个候选组为 `【生图分组】image2超分`、`【生图分组】Image2-满参`。初次及旧中质量选择为 null，提示重新选择。换分组和型号不刷新上游；实际清单刷新才更新快照。报价按显示 revision 额外防迟到，0 值、来源白名单、大小/超时限制、无表达式执行和无 Key 读取规则保持。

接口详见[连接契约](../connections-v1.md)。连接摘要的旧默认字段保留兼容，新界面以 displaySettings.default* 为准。价格组不改变实际生成分组。

## 验证记录

测试环境为 Windows/Node，使用隔离临时 SQLite、合成凭据及本地 loopback 上游。新 model-display-settings 专项覆盖初始化冻结、刷新新增/缺席/失败、重启、CAS与线路/身份冲突、默认/分类拒绝、身份隔离、引导事务、旧价格组清空、两型号两组报价、分组变更迟到保护、受保护HTTP与已有草稿保留。

已有报价专项更新为显式选择现行组，继续覆盖匿名、超时、重定向、畸形/超大数据、缓存、在途合并与身份/线路防迟到。model-catalog 测试桩将匿名价格请求与模型请求分开，避免请求计数误计及共用迟到 resolve 挂起。连接测试只对上游实际返回型号断言 visible，新增配置型号不能伪造上游可见性。

结果：122 项，121 通过、0 失败、1 跳过；跳过是既有 Windows 符号链接权限限制。范围包括 8 项新增模型显示专项、13 项报价专项以及连接、B3、存储和分组回归，不代表全量后端测试通过。受影响源码语法检查及本批文件 `git diff --check` 通过。

首轮暴露并修正的测试前置包括：新增初始 Sunburst 不能使“全部配置型号均上游可见”的旧断言继续成立；自定义来源不应被套用内置列表；model-catalog 的价格请求需要独立桩；两项旧 HTTP 排队测试的环境并发变量已不控制生命周期 v2，须像其他专项一样显式保存 taskExecution=1 才能验证“清除时仍在队列”的行为。上述修正未放宽生成/凭据断言，也未改生产并发。新增 nullable IPC 用例曾错误对自定义连接携带内置线路 null，改为遵循原 check 接口省略该字段后通过。

最终补核手工分类无法授予另一媒体协议：flare 被手工分为 video 时不投影可提交，不能成为视频默认；真实 HTTP 同时 PUT 相同 revision 只有一个成功，另一项明确冲突。新草稿验证覆盖未分组与自定义剧本，既有隐藏草稿在重启后仍保留。
