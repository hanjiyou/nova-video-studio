## 2. 时间预算与生命周期（新规划）

### 2.1 配置及展示

| 设置 | 默认 | 含义 |
| --- | --- | --- |
| 图片生成时限 | 保持现有 120 秒 | 从真实派发到收到并接受有效原生成结果 |
| 视频生成时限 | 保持现有 300 秒 | 含提交、远端等待、原 ID 查询和结果解析 |
| 图片结果下载时限 | 用户确认 30 秒 | 一次结果下载尝试，包括来源刷新、传输、校验和保存 |
| 视频结果下载时限 | 用户确认 180 秒 | 同上，独立于生成预算 |

下载设置建议采用与生成设置一致的整数 30–1800 秒范围，作为本规划实现默认方案；此范围是方案选择，不冒称用户逐项指定。设置页归入“任务控制”，分别标明“生成时限”和“结果下载时限”。帮助文案：生成成功后重新计算下载时间，下载时间包含校验和保存。原总时限数值保留，修改其显示解释及新任务语义，不能静默改写旧任务快照。

建议沿用 taskExecution 设置对象并新增 imageDownloadTimeoutSeconds/videoDownloadTimeoutSeconds；扩展版本与 revision 校验。读取旧设置时只为新增字段提供 30/180 默认，保留其他已保存值。升级客户端首次明确解释预算拆分；旧格式写入须有显式兼容分支或返回清晰冲突，不允许覆盖新增字段或重置用户值。

### 2.2 交接和截止

1. 本地排队不算生成时间；派发时启动冻结的生成预算，上传参考图、响应等待、接收解析和远端查询均消耗它。
2. 只有收到可识别、来源校验通过的原生成结果，才转入下载。远端 completed 但没有有效候选不能伪造成功。
3. 在事务中保存结果清单/恢复凭据标记、生成阶段完成事实和下载队列，再使生成计时器失效。使用阶段标识和尝试 token 保证旧计时器不能终止新的下载；交接与超时竞争只有一个胜者。
4. 原生成预算结束于上述交接；task completed 仍必须等所有结果校验保存及关联事务成功。不要提前把历史 localOutcome 简单改成整任务 completed；新增 generationOutcome/generationFinishedAt 等明确字段或等价版本化投影，保留旧 localOutcome 的历史含义。
5. 首次下载排队时冻结当时的下载设置；实际获得下载执行资格时启动完整预算，下载等待独立显示，不提前消耗。名额仍覆盖整个本地处理，不因拆分预算增加无限并发池。
6. 首次下载和手动重新下载均使用新的 downloadAttemptId；手动重试在动作被接受时冻结当时设置，实际执行时启动。图片默认 30 秒，视频默认 180 秒，不取原生成剩余时间的最小值。
7. 一次下载尝试共用一个绝对截止：刷新链接、重定向、多文件、校验、保存不续期。现有 worker 120 秒硬上限须移除或改为注入本次截止，否则视频 180 秒和可配置值无法生效。解码子操作上限仍可保留，但不得超过本次剩余时间，不额外赠送 90 秒。
8. 设置变化只影响后续下载尝试；执行中的 attempt/deadline 不变。速度停滞只是状态提示，不新增未经约定的自动失败阈值或自动重试。
9. 下载失败保留原生成结果及生成完成事实。取消下载只取消本次本地下载，不取消已完成生成、不退款、不删除已验证文件；允许按恢复能力再次手动下载。

例：视频生成用 290 秒后成功，仍有完整的 180 秒下载预算；整条本地流程可能超过 300 秒。图片生成 110 秒成功后有完整 30 秒。生成达到自身截止但尚未取得有效结果，不能借下载预算延长生成。

### 2.3 旧任务、重启与恢复

- 新任务带显式生命周期规则版本；旧记录保留原 deadline/localOutcome/耗时，不根据新默认补造旧执行过程。
- 迁移时旧活动生成按旧规则恢复；已有原结果的旧失败任务可由用户明确进入新独立下载尝试。旧下载跨重启停止并保留恢复能力，不自动领取新预算。
- 重启后的下载尝试记为中断并停止旧计时，最后字节只作历史显示，速度清零；用户点击重新下载才创建新 attempt。
- 原有 inline/安全持久 URL/原 ID 刷新路径继续复用。签名 URL 无 ID 的跨重启恢复见第 7 节用户已确认的存储边界。
- 已完成作品不因迁移、刷新或重复动作重复创建；文件缺失恢复继续保留现有受控入口，不能把已验证完好的文件重新下载当成默认行为。

## 3. 界面要求

### 3.1 原位置增量

- 保持当前侧栏、左参数右预览、最近图片/视频任务区域和卡片排列；不新增独立下载列表或底部设计示例区域。
- 当前任务卡片状态区显示生成中、下载中、校验中、保存中、完成；右侧预览在选中未完成任务时显示同一状态。详情展开文件级信息。
- 已完成卡片基本不变；下载前无可用本地预览时使用原占位图标，不能生成假缩略图。
- 下载失败且确认有生成结果：显示“图片/视频已生成，下载失败”、具体原因、已收字节和本次耗时；明显的“重新下载”，保留“任务详情”和“移除任务展示”。活动下载期间不允许移除展示。
- 点击重试立即显示“正在请求重新下载”，接受后显示等待下载/下载中；提供“取消下载”，不误用“重新生成”按钮。重新下载与“以相同草稿新建任务”必须区分。
- 原生成耗时冻结，另显示“本次下载：35 秒 / 时限 180 秒”；截止时间放详情，不能拿旧生成截止暗示下载已经到期。

### 3.2 进度契约

独立 downloadProgress，不复用上游 remote_progress。字段建议如下（D01 冻结具体 schema）：

| 字段 | 单位/语义 |
| --- | --- |
| attemptId、attemptNumber、revision | 尝试 ID、包括首次在内的序号、任务单调状态版本；retryCount=attemptNumber-1 |
| phase | waiting/refreshing/downloading/validating/saving/completed/failed/cancelled |
| fileIndex、fileCount | 原结果列表中的 1 基序号与总数；列表身份独立于临时 URL |
| receivedBytes、totalBytes | 当前文件本次实际接收字节；可信总大小未知为 null |
| bytesPerSecond、percent | 平滑速度；百分比未知为 null，不能用 0 代表未知 |
| savedFileCount、overallReceivedBytes、overallTotalBytes | 已完整保存数；本次网络实收累计字节；原结果总量全部可信才提供总大小 |
| reusedBytes、completedBytes | 从已有已验证文件复用的字节、当前结果集合中已接收/保存的有效字节；与本次网络传输量分开 |
| elapsedMs、lastByteAt、startedAt、deadlineAt、timeoutSeconds、stalled | 单调耗时、时间戳、冻结预算、停滞观察；未开始的 startedAt/deadlineAt 为 null |

- 原始单位字节、毫秒、字节/秒；显示十进制 KB/MB。速度按单调时钟最近 3 秒滑动窗口，最多每 500ms 推送一次；3 秒无字节归零，5 秒无字节显示暂未收到数据，不自动改网络。
- 关键阶段/首包/文件切换/错误/完成立即更新；停止后停止采样定时器。前端断流超过新鲜度窗口显示连接中断或进度暂不可用，不能一直展示旧速度。
- 最终响应合法 Content-Length 且与实际读取口径一致时才可信。缺失、编码转换等情况下总量未知；非法/矛盾长度仍按完整性规则失败，不能靠“未知”掩盖损坏。长度超过单文件预算直接拒绝。
- 已知：已下载 1.8 MB / 4.2 MB · 620 KB/s · 43%。未知：已下载 1.8 MB · 总大小未知 · 620 KB/s，不显示数值进度条。
- 下载 100%不等于完成：响应正确结束、完整性/媒体解码、正式文件持久化及最终关联均完成才终态成功；不得把 99%伪装成校验进度。
- 多文件显示“第 2 / 4 个文件 · 整体已保存 1 / 4”。每个文件阶段可不同；不得用文件数平均代替字节加权比例。全量长度不齐时仅显示整体文件数；已知时整体百分比使用有效 completedBytes/overallTotalBytes，不能用含失败重传的网络累计量计算超过 100%。
- 内联结果显示“结果已接收”，直接进入校验保存，不虚构二次网络下载速度。刷新链接后重新取同一文件时本次文件字节归零，并以传输序号区分，保留真实累计网络字节。

## 4. 恢复、安全与完成门槛

- 复用 retry-download；从服务端投影 canRetryDownload/recoveryKind/recoveryReason 等能力，卡片和详情一致。不能只按 download_failed 判断，需覆盖已确认结果的下载阶段超时/取消/重启中断，且不能放开结果未知任务自动生成。
- 动作带 requestId，数据库原子去重；同一 requestId 回执丢失只返回原尝试。跨卡片/详情/连接重复操作只能有一个活动尝试，用户新一次明确操作才允许新尝试。409 容量满时提示稍后重试，不假装已下载。
- 沿用原任务 ID、连接版本、适配器版本、输入来源及输出目录绑定。刷新仅使用经过能力确认的 adapter.poll 原上游 ID，保留 Retry-After 与安全重定向限制；不猜接口、换连接、换模型或 POST 生成。
- 新增下载文件检查点：原结果序号/稳定身份、验证元数据、assetId 和完成状态。每个文件在验证落盘后提交检查点；恢复时再次核对文件与摘要。失败 .part 不作为作品，也不跨尝试按字节复用。
- 刷新结果地址时核对原任务、候选数量/身份/顺序，不能仅按数组位置复用内容可能已变的结果。无法证明相同输出时不得错误绑定缓存。
- 全部文件通过后才在事务中完成输出关联与任务完成；崩溃发生在文件落盘与关联之间必须可恢复，不误删共享资产，不重复建作品。
- 旧 attempt 的进度、错误、校验和保存回调经过当前身份、状态和版本检查；没有通过检查就丢弃，不能只在 UI 防抖。
- 明确为重新下载整个未保存文件；未实现并验证 Range、ETag/If-Range、206/Content-Range、内容身份和最终完整性前，不称为字节断点续传。

错误分类：DOWNLOAD_TIMEOUT（区分下载预算/生成预算）、连接/DNS/TLS失败、链接过期、原连接鉴权失败、DOWNLOAD_INCOMPLETE、MEDIA_INVALID、磁盘满/文件锁/无权限/写入失败、来源不可恢复。HTTP 403 不一概归为过期；不能把超时泛化成磁盘错误。网络提示仅建议检查网络或代理接管，不判断用户是否开代理，不修改 Clash 或切换节点。

## 5. 数据、HTTP/WS 和诊断

- 追加数据库迁移，不改旧 checksum；保存规则版本、设置快照、阶段起止、结果清单、文件检查点、动作去重和尝试摘要。已有来源保护、备份和事务机制保持。
- 传输高频进度在内存合并，每 500ms 最多广播；同一任务的关键事件/终态立即持久化，约每 5 秒保存进度快照，不能每 chunk 写 DB。断电可能丢失最近几秒观察，诊断明确最后采样时刻而非伪造终止字节。
- HTTP 单条/列表/动作响应与 WS 消费统一 DTO。HTTP 读取应能合并当前内存最新值；重启使用持久快照并标记非活动。订阅只给已鉴权会话，不广播完整结果源。
- 前端共用任务状态存储与组件；保留 HTTP 首次加载、重连及低频兜底，按任务 revision 拒绝乱序；历史旧 ID 消息不能重新激活已结束尝试。使用现有 WS 路由，避免另建无鉴权通道。
- 诊断采集和导出均白名单：attemptId/序号、重试次数、文件序号、已收/总字节、耗时、阶段、最后数据时间、失败原因、预算来源、HTTP状态、复用文件数。失败终态写最终快照，修复只有成功 download_received 才进入摘要的问题。
- 事件保留有界早期边界与滚动尾部；最新尝试摘要和总次数必须保留，较旧尝试摘要建议保留最近 10 次并注明截断。任务历史和作品不随诊断裁剪删除。
- networkMode 标为应用请求策略，系统代理/TUN 接管不可观察时为 unknown；direct 不是“未开代理”。禁止 Token、签名 URL、原始 Base64、完整敏感路径、原始远端正文或解码 stderr 出现在前端/日志/导出。

## 7. 已确认边界与不可承诺范围

1. 无 ID 的同步签名 URL 跨重启恢复：用户最终选择保持原存储规则，不新增加密。临时签名 URL 仅本次运行内存交接；重启后无可查询原 ID 且无全部有效文件检查点时，明确提示无法恢复，不自动重新生成。安全持久 URL、内联资产和可原 ID 查询结果保留原恢复能力。此为确认范围，已无待决项。
2. 已过期且无法查询的链接无法恢复；旧版重启已丢失的内存链接不能补回。不得为恢复偷偷重新生成。
3. 下载预算包含来源刷新、多个文件、校验和保存，范围30–1800秒，是本次规划的具体落地建议；实施前结合D01校验冻结文案。如后续用户希望网络传输与解码再分预算，应另立变更，不在代码中暗自增加时间。
4. 不实施远端字节续传、自动修改代理、自动重新下载、自动生成或新增模型能力；不改变真实服务/付费验收门槛。
