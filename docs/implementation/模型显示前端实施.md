# 模型显示前端实施

日期：2026-10-28。状态：代码和离线验证完成，主会话已完成本轮范围审核；未提交、推送、打包、发布或真实生成。本报告对应[当前实施计划](../模型显示配置与通用图片接入计划.md)，不替代安装态或真实服务验收。

## 实现范围

- 设置增加“通用 / 连接与模型 / 存储 / 关于”可操作导航。标签切换保持连接表单挂载，保留未保存的名称、地址、Key输入与现有首次向导；任务控制、最近视频数量、目录选择、诊断和应用更新均可抵达，版本入口直接定位“关于”。
- “连接与模型”顶部显示真实连接名和保存的验证状态，CN/COM通过现有宿主保存线路并带版本/线路CAS；刷新调用真实只读模型检查，不发生成请求。
- 图片与视频双卡来自当前API清单分类结果，各自搜索、显示数量、勾选、接入状态和明确设默认。双分类使用后端`submissionEnabledByKind`逐类判断，手动分类不会赋予生成能力。旧选择被改出原分类时提供明确的“移除旧选择”入口。
- 模型勾选、默认型号与图片参考价分组通过一次`PUT model-display`原子保存。未保存状态、取消、保存失败和冲突均有明确反馈；刷新不覆盖脏值，新发现型号不自动勾选。隐藏当前默认需用户明确另选默认，或隐藏该类全部型号，应用不自动替换。
- 图片参考价组从API候选读取；旧中质量组不会自动映射，初始空值提示选择。报价按当前完整型号和保存的参考价组查询；支持已配置的flare和sunburst，移除ImagePrice中对flare的写死判断。报价资料、型号、连接版本、线路、显示revision变化均隔离迟到结果；报价失败不阻止原本可生成的草稿。
- 生成下拉仅列勾选且当前可见/显式自定义的型号。已有草稿型号被隐藏时，下拉关闭态以禁用且隐藏的占位项呈现“型号 · 已隐藏”；展开不提供此型号可选项。模型下方amber提示与“选择模型”按钮聚焦并尝试打开原生选择器，保留提示词、参数和参考图，禁止生成；换可用型号后提示消失。
- 图片提示词置于模型提示下方，隐藏情境仍可直接看到原内容。未接入与未开放分别使用简明产品文案，生成拦截不再显示“成功协议证据”等内部术语。
- 默认项仅供新草稿使用，既有型号不被静默替换。向导优先新display默认；图片独有连接、无已接入型号的自定义连接可以将缺失类型设为空并继续，明确传`null`，兼容较旧宿主的原输入形式。
- 同一连接的线路变化保留脏值，凭据版本变化保留当前编辑但阻止直接保存到新身份；显式重新读取后再核对。父级与设置组件拒绝同scope较低显示revision的迟到快照，已确认保存的设置不会被旧响应回滚。

## 关键文件

- `frontend/src/components/workbench/WorkbenchSettings.tsx`：设置导航与原入口保留。
- `frontend/src/components/workbench/ModelDisplaySettings.tsx`：显示配置、真实线路/刷新、默认和CAS交互。
- `frontend/src/components/workbench/DefaultSettings.tsx`：原向导、现有分类管理复用、独立存储入口。
- `frontend/src/components/workbench/DraftEditor.tsx`、`ImagePrice.tsx`：隐藏草稿提示、型号选择和当前分组参考价。
- `frontend/src/lib/connection-client.ts`、`workbench-model-catalog.ts`、`workbench-generation.ts`：API契约、逐类提交状态、scope/revision约束及生成条件。
- `frontend/src/types/nova-desktop.d.ts`：向导缺失类型默认值支持null。
- `backend/connections/service.js`只补逐类状态投影；对应双分类回归加在`backend/test/model-display-settings.test.js`，既有默认校验保持后端规则。

## 过程中失败与范围限制

1. 第一轮相关6文件68项为58过10失败，主要是旧中质量文案、旧图片能力fixture版本/元数据及分类入口调整后的查询。均已按当前契约修正，受影响用例包含在最终136项中。
2. 一次扩大到全部前端的运行：92文件925项，917过8失败。两项为本轮需要同步的确定性fixture/导航变化（未配置连接时任务控制移至“通用”；线路预检fixture缺route/revision），已修复并在最终相关回归通过。
3. 该全量运行另外两项为最近视频任务测试的收集堆栈错误和启动等待失败；这两项所属的最近视频文件最终单独纳入11文件受控并发回归，12/12通过，原全量失败记录仍保留，未将其描述成已证明的既有基线。
4. 余下四项位于未改动的多参考图库选择测试1项（STACK_TRACE_ERROR）、desktop CDP默认配置1项及旧WorkspaceShell Agent会话2项。本轮没有修复这些无关模块，也没有完成其基线复验；因此全量925项不记为通过。最终结论限定为上方受影响范围。
