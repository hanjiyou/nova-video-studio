# 作品库预览与详情实施规划

日期：2026-10-27。状态：LP01 / LP02 实现与离线验证完成；主会话已反馈源码及独立18项定向交互审核通过，文档与新增静态布局证据交主会话收口。本轮不提交、推送、打包或发布，不做真实生成，不读取真实凭据或用户数据库。

## 需求与范围

当前 `WorkbenchLibrary` 卡片单击调用 `onDetails`，而 `TaskDetails` 没有播放器，历史视频只能看到封面。本轮在原作品库增加图片 / 视频预览，并保留独立任务详情入口。

- 取消卡片封面 / 内容区鼠标单击打开详情；双击在当前页面上方打开预览弹窗。封面可聚焦，Enter / Space 打开预览。
- 图片按原比例 contain 显示大图；视频使用原生 `video controls`，由浏览器提供播放 / 暂停、seek、音量和全屏，不要求自动播放或自绘控件。
- 卡片下方增加“任务详情”，沿用原 `onDetails`，与“移除记录”并排并在窄屏合理换行。选择图片、详情、移除分别独立，不冒泡打开预览。
- 复用 `WorkbenchDialog` 与 `AssetActions` 的另存副本 / 打开结果目录；不改公共弹窗的无关行为。
- 关闭 X、Esc、遮罩后停止视频并释放播放源，底层筛选、页码及已选图片顺序保留。
- 只使用现有受管本地媒体 `previewUrl`；首个输出维持现有规则，不扩展多文件画廊，不引入后端 / 存储变更。
- 无输出、生成中、下载失败或文件缺失时显示“暂无可预览结果”或真实原因；图片加载失败、视频播放失败有中文提示。独立任务详情仍可用于现有恢复操作；预览不触发生成或自动重下载。
- 保留作品类型 / 状态下拉、搜索筛选、分页、图片选择引用、删除行为与工作台最近 6 个规则。
- 弹窗在常规桌面与 390px 视口不产生横向溢出。按已有资产信息显示并处理实际 error，不增加异步预检框架。

## 验收

1. 单击不弹窗；双击图片 / 视频分别打开正确媒体；任务详情按钮只调用原详情。
2. 图片选择、顺序、移除独立；第 2 页旧视频可打开，关闭后筛选、页码及选择顺序保持。
3. 无输出 / 下载失败 / 缺失文件 / 图片加载失败 / 视频解码失败均有中文状态，不显示空播放器，不触发重新生成或自动下载。
4. 关闭视频会停止并释放播放源；封面键盘 Enter / Space 和弹窗 Esc 可用。
5. 相关原回归不退步；运行相关 Vitest 与 `npx tsc --noEmit --incremental false`，记录精确结果。
6. 尽量复用既有离线实际组件截图方式核对桌面 / 390px 布局；不为截图搭建大框架。JSDOM 的控件 / 事件断言不等于真实播放和 seek 验收，实际安装态交互另列限制。
