# 安装包差量更新修复计划

日期：2026-10-27。用户授权深入设计、成批任务、子代理开发及主会话审核。本轮不提交推送、不发布新包、不覆盖本机安装、不操作电脑B；允许合成数据与隔离编译/本地传输验证。当前状态：U01–U03已实施，源码与定向离线范围主审通过，详见[主审记录](implementation/安装包差量更新主审记录.md)。基线：3.6.8已发布，源码8c486f6；该版本尚未包含本专项修复。

## 1. 已确认问题

本机3.6.5→3.6.6两次差量尝试、3.6.6→3.6.7一次差量尝试均记录differential_fallback。后一轮下载133795485字节，与完整安装包一致。诊断没有丢失事件或写入失败，但只保留回退标识，无法追认每次的具体错误。

安装器NSIS从package.name生成nova-image-updater缓存目录；afterPack仅改写app-update.yml为com.novaimage.studio.github-test-updater。运行时查找的installer.exe不存在，pending里有下载的新包及索引。另一个目录仅有更早旧包；不能把它当作当前版本。目录不一致已确证，安装后复制覆盖/失败行为仍需沿编译模板验证。

pending只保存待安装的新包是正常结构。差量更新需要当前已安装版本的完整基础包和匹配索引，从旧包复制未变块、下载变化块，再完整校验新包；不是中断续传，也不保证每个版本都有显著节省。

## 2. 最小实现边界

- 一个权威缓存身份贯通安装器编译、运行时app-update.yml、清理与验证；保留既有appId、用户资料目录、渠道和签名门槛，不修改node_modules。
- 首次安装、手动覆盖、应用内更新均把已安装版本的基础包放入对应缓存。基础包变化不得配用旧索引；无法可靠获取新索引时安全失效旧索引，后续按原供应商协议获取，不伪造索引。
- 复制/磁盘失败不能留下可误用的半包或假成功状态；基础包只服务下载优化，不导致用户资料丢失或既有应用不能使用。最终安装包始终完整校验。
- 旧安装兼容默认允许一次完整下载，安装修复版后自动建立正确缓存。不得扫描或盲目搬另一个渠道缓存，不要求用户手动复制/改配置；不为减少首次全下载新增复杂修复服务。
- 状态区分尝试差量、实际差量传输、回退完整下载及可信的完整缓存复用；证据不足只显示准备下载。下载尝试重置，不能沿用上一轮模式。进度单位及分母来自真实更新器语义，不把本地拼包字节当网络节省。
- 回退原因白名单分类，保留缺失旧包、索引、传输、校验及未知等可证实原因。不得保存原始URL、路径、Token、响应或堆栈；不因分类猜测网络/代理状态。
- 不改变发布脚本完整远端字节校验、不新增Range断点续传、不切代理或覆盖用户安装。

## 4. 验收矩阵

- 路径：安装器最终定义与运行时目录一致，渠道隔离，中文/空格路径，不修改用户资料。
- 缓存：首次、手动覆盖、应用升级三入口；旧包缺失、损坏、陈旧索引、复制/磁盘失败、同路径源文件、重复安装；错误缓存不用于误拼。
- 两版本：本地合成服务和可控相似包，使用锁定真实NsisUpdater；验证Range请求、实际响应字节低于整包且最终SHA512一致。另测旧包缺失/损坏、错误索引、Range失败安全回退整包，重启完整缓存复用。
- 不再仅通过测试手动预填installer.exe就宣布安装闭环通过。需验证安装缓存操作接下一次下载；若未执行真实NSIS安装，明确模型/隔离编译与实际安装的界限。
- 界面/诊断：差量尝试不冒充成功，模式变化/失败/重试准确；无敏感字段；原安装完成页与更新准备回归；完整TS及影响范围测试。
- 电脑A与电脑B分别留待安装态验收：正常安装修复版后，再更新下一测试版本，比较实际下载字节并验证启动/数据保持。本机证据不得冒充电脑B结果。

## 开发期补充：缓存可信边界

采用固定临时包→与本次安装源SHA512对比→发布基础包的最小流程；仅保存schemaVersion/appId/version/sha512的基础包标记，下载前验证当前版本与实际文件，不扩展成通用恢复系统。旧安装没有标记允许完整下载一次，不自动搬旧缓存。

锁定更新器在“下载完成、尚未安装”阶段就可能把新包索引提升到缓存根，但基础包仍是当前安装版本。必须覆盖“下载后不安装、再下载下一版本”的错配风险；不能只在安装完成时删除旧索引就宣布一致。实现可安全失效本渠道根索引后重新获取当前版本索引，或验证索引与基础包一致，需选择最小可靠方案并记录成本。
