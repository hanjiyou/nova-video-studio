# G03 归组、目录重命名与历史整理

日期：2026-10-27。状态：核心与后端接口集成已完成，主会话最终独立运行当前 G03 核心 23 项及 HTTP 集成 3 项，共 26/26 通过；界面与整体审核以总体验收记录为准。未提交、推送、打包、发布或执行真实生成，未读取真实用户数据库、凭据或验收原件。

## 实现边界

新增 `backend/storage/group-moves.js`，由存储层注入数据库、分组/根目录定位、安全文件解析和任务真实 IO 活动守卫。拖拽和菜单调用同一 `moveTask(taskId,{groupId,requestId,expectedRevision?})`；前端不提交文件路径。归组粒度是整条任务，覆盖其全部正式输出。没有正式输出的终止任务也可修改当前归属。

当前分组与不可变提交快照独立：改组只修改当前成员关系、输出资产关联、当前输出定位、当前下载检查点和可变恢复候选中的本任务输出 ID。旧提交快照、输入素材关联、默认/分组草稿引用、原目录版本保持。现有根目录切换只影响后续任务；显式改组仍在原任务根目录完成。

活动判断使用现有 `localOutcome` 规则，并检查下载等待/执行记录、未完成下载尝试和注入的真实 IO 守卫；排队、回执未知、暂停查询等尚无本地终态任务不能迁移。取消后尚未退出的真实 IO 同样阻止迁移。普通同组请求直接返回无变化，不创建目录、操作记录或成员关系修订；同组旧摘要文件只能通过明确的历史整理操作迁移。

## 文件与事务边界

追加迁移 v13 中的小型 `group_file_operations` 记录使用唯一 `requestId` 保存操作身份、计划、状态与结果，不修改既有迁移 SQL/checksum。操作流程如下：

1. 校验组、任务终态、成员修订、所有源文件的字节数/SHA-256，以及全部目标路径、已有文件和受管定位冲突。
2. 持久化整个任务的来源、目标、目标资产 ID、检查点与预留定位计划。
3. 向目标受管目录独占复制私有临时文件，校验并同步文件，再通过独占硬链接发布目标。临时硬链接保留到逻辑提交，作为中断回滚时目标确属本操作的物理身份证据。
4. 一个 SQLite 事务创建新输出资产、重绑全部正式输出和有效检查点、更新当前输出定位与当前成员关系，并记录 `committed`。用户不会读到一半输出属于新组的状态。
5. 校验已提交目标后移除本操作临时链接；只有能证明没有任何其他引用、没有共享物理别名且来源为受管生成文件时，才释放源文件和无引用资产记录。

源清理检查任务输入/输出、默认/分组草稿、下载检查点、遗留关联、不可变输入快照、恢复候选和持久提交意图。共享文件、导入原件、旧内部/遗留来源保留。无法核实其他根目录下的别名时保守保留源副本，不为去重损坏目录对应。

部分下载的有效检查点一并迁移。缺失、未校验或与正式输出不一致而未迁移的检查点，在逻辑提交内只删除该任务的当前恢复关联；旧资产和文件保留。即使旧文件随后重新出现，也不能从旧组直接恢复绑定；原内联资产仍可作为恢复来源，经现有校验/发布器写入当前新组。

目标已有文件绝不覆盖。多文件复制中断、数据库事务失败时，原成员关系与原正式输出不变；回滚只删除同时匹配记录摘要、大小以及私有硬链接文件身份的目标。目标被替换、目录被替换或清理受阻时保留现状并记录 `needs-recovery`，不宣称已经回滚。

## 重启恢复与分组管理

`recover()` 在启动或明确恢复操作时尝试恢复并返回未解决操作描述，不阻止启动或历史读取；`recoveryStatus()` 与历史预览是纯读取，不在 GET 中修改文件。`recover({groupId})` 或任务/组作用域只阻止该操作涉及的来源/目标组发生新提交、迁移或管理；其他分组可以继续使用。有效 UUID 统一为规范小写后检查作用域，不能以大小写差异绕过守卫。提交前未完成操作回滚，提交后未完成操作核实目标并安全收尾；重复请求返回同一成功结果，失败请求保留失败结论，需要新请求重试。

重命名先检查组内活动任务、真实 IO、尚未形成任务的已保存提交意图，以及全部已登记根目录中的目标冲突。该组文件及物理别名如果被其他组的活动任务输入、下载检查点、恢复候选、不可变快照或待提交意图引用，也拒绝重命名，避免中断异步上传/解码；取消但 IO 未退出的任务仍由同一个真实活动守卫保护。根目录别名按实际规范路径只处理一次。每个原目录的设备号/文件号在计划中保存；移动前、提交前、回滚和提交后恢复都核对同一物理目录，外部替换目录不会被误认成本操作的目录。

所有物理位置成功重命名后，在一个事务中追加新目录版本、更新当前映射/成员/输出定位/资产位置和显示名。路径按组件重写，中文及 emoji 名称不依赖 JavaScript UTF-16 长度与 SQLite Unicode 索引互换。旧目录版本与提交时组名保留历史。任一根目录不能处理时不跳过或假成功；需要恢复的组继续受保护。

归档不删除历史或文件；归档组禁止新提交，支持取消归档。系统未分组不能重命名、归档或删除。自建组只有在没有成员任务、作品、持久提交意图、草稿内容且所有登记目录确实为空时才能删除。完全清空的草稿不阻止删除；包含提示词、模型、参数或素材的草稿仍受保护。删除只移除已核实的空目录，保留隐藏组记录和不可变目录版本；释放名称键后允许创建显示名相同的新组，新组使用新的稳定 ID。

## 显式历史整理

升级只登记逻辑未分组，不移动旧摘要文件。`previewHistory` 只读取记录与文件，列出任务、源/目标和冲突，不创建目录/映射或移动文件。`organizeHistory({taskIds,requestId})` 仅处理用户明确选择的 1–100 条任务，记录该请求的选择范围，每条仍调用同一个整任务迁移核心。

选择范围中某条失败不隐藏已成功条目，也不阻断后续条目：返回每条 `ok`、任务/操作 ID 或具体错误，以及 `succeeded/failed` 数量。相同请求重复调用保持结果；同一请求修改选择范围被拒绝。新的明确请求可以重试失败条目。前端需呈现部分成功及具体原因，不把批次概括成全部成功。
