## 实现与接口

追加schema v12，保持v1–v11 SQL/checksum，沿用一致备份、事务和失败回滚。稳定系统组为未分组，ID `00000000-0000-4000-8000-000000000002`。组身份跨已登记根目录保持一致；每个根目录的组目录有独立不可变版本，当前版本映射单独保存。重复选择同一物理根目录识别已有受管目录，不接管用户同名文件夹。

GET/POST `/api/nova/storage/groups`读取/创建组（创建体仅`{name}`）。GET/PUT `/api/nova/storage/groups/:groupId/drafts/:mode`存组内草稿；旧`/storage/drafts/:mode`仍是未分组别名，旧revision和有序素材保持。自建组使用独立草稿表，所有引用统计和显式文件清理同时检查两套草稿引用。

任务创建接受groupId，未提供时新任务冻结未分组。快照增加groupId/groupName/groupDirectoryVersionId及原根目录版本；groupName保留原提交事实。task_group_memberships和assets当前位置与不可变快照分开；DTO提供当前groupId/groupName/groupRevision、submittedGroupId/submittedGroupName和完整outputLocation。冻结字段进入提交意图canonical比较及localRequestId去重。已有旧任务快照不补写分组字段、不改字节。

新成品写入`保存根/assets/剧本名/图片或视频/可读名称`；参考导入和内部候选继续内部摘要存储。原任务创建时间按首次分配时的本地时区生成`yyyyMMdd-HHmmss_描述_稳定短编号[_序号].扩展名`，完整名称持久化到任务输出位置表，重试/重启复用。说明由原提示词清理裁切，不请求AI。组名最多48个UTF-16单位，描述24、完整文件名100、受管完整路径240；临时目录和发布临时文件也检查同一上限。编号为任务ID+输出序号SHA-256前12位；初始碰撞安全分配后缀，已预留名称被未知文件占用则拒绝覆盖。

SHA-256继续验证完整性。assets原表的全局摘要UNIQUE是SQLite表约束，不能独立drop；v12保留每条素材及四类引用，重建为仅内部/旧对象按根摘要去重，新成品允许同字节在不同组保有独立受管文件。availability触发器及全部原FK/索引恢复，迁移后foreign_key_check/quick_check通过。

发布先登记unverified/missing的精确文件所有权，再独占原子落盘，最后改verified/available；中断后可复用同assetId。结果只有全部校验、落盘、关联的既有事务成功后才完成。取消、截止、一次生成POST、原ID恢复和凭据规则保持。

## 根目录与边界

新的提交意图采用当前根；已准备的提交意图、旧任务保持其冻结根。修改设置不移动旧文件。G03显式归组仍在原任务根目录完成，重命名以当前映射更新新目录版本；不会直接改不可变版本。旧摘要路径双读兼容，升级不移动旧文件。

使用Node Unicode path/fs及媒体工具参数数组，合法中文、空格、括号、&及emoji不转义成命令。拒绝Windows非法字符、控制/孤立代理项、设备保留名、尾点/空格、大小写或规范化重名、穿越、未知同名目录。每个受管目录组件检查真实路径及联接/符号链接，生成提交前和实际派发前均检查目录和可写探针，防止可预判保存错误发生在收费POST后。
