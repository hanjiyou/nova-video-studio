## 缺陷与修复边界

首轮 Node v24.14.0 的原生 `FormData` 与 root undici v8.10.0 的表单品牌不同。把原生对象直接交给独立 `undici.fetch`，实际接收端得到 `text/plain;charset=UTF-8`，正文为 `[object FormData]`，没有 multipart 字段和图片。此前对象级预检能检查原图字节与顺序，却不能证明实际传输；首轮两项 HTTP 400 仍是已观察到的失败，未保存原始远端错误，不能断言本地缺陷是其全部原因。

修复仅在 T15 专用 undici 传输边界将原生表单逐项转为配套 `undici.FormData`，保留重复字段、文件名、MIME 和原 Blob 字节，由传输自行生成边界；不手写 Content-Type，也不修改生产视频适配器字段或能力等级。实际 Electron 43.4.0 原生直连及 `net.fetch` 系统代理路径的四项本地接收端检查均通过，未发现同一缺陷，故没有扩展生产网络改动。

修复前相同代理隧道回归为单/双参考 2 项失败、JSON/GET 1 项通过；修复后单/双参考的实际 wire、JSON/GET 和有界错误诊断 8/8 通过。配合原有适配器、实际 HTTP、提交不明/重启/凭据边界共 66/66 通过，定向 lint 和语法检查通过。证据见 [修复前](t15-retest-evidence/wire-before-fix.log)、[修复后](t15-retest-evidence/wire-after-fix.log)、[66 项回归](t15-retest-evidence/backend-regression.log)、[原生桌面四项](t15-retest-evidence/native-wire.json)。
