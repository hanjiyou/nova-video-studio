## 运行行为

- 图片与视频默认各 3 个名额，分别读取 taskExecution 配置。一次名额覆盖提交、远端等待、轮询暂停、下载、验证和保存；降低配置不强杀现有任务，提高配置唤醒排队。异步预检中的任务计入入场数，未派发且预检暂停的记录不占名额。
- 调度不等待整个 submit 完成；每个视频独立查询，同 ID 最多一个在途 GET。下载按已入场任务分别执行，慢图片 / 视频下载不建立新的全局串行锁。localRequestId、不可变输入和原连接 / 适配器约束保留。
- 新任务创建时保存 I01 时限快照，首次真实派发前持久化 attempt 和 deadline，重新读取 committed row 后才传给适配器。图片 120 秒、视频 300 秒覆盖参考图上传 / 请求构建、请求头与正文等待、解析、远端排队和退避、下载、验证、保存，不按阶段重置。
- 单进程以单调时钟执行预算；重启从持久 deadline 计算剩余预算。截止已过、持久时间非法或墙钟倒退到派发前，保守本地超时。请求本身可以早于总截止失败，但不会获得新的完整预算。
- POST `/api/nova/tasks/:id/cancel`（兼容内部别名 cancel-task）可取消排队、运行中任务或独立下载尝试；重复取消稳定。终态通过条件更新争抢一次写入权，取消 / 超时停止本地等待并释放逻辑名额，不宣称远端取消或退费，不自动 POST。
- 执行 token、信号和检查点贯穿适配器、下载、媒体验证与资产绑定。迟到结果不覆盖本地终态，不绑定取消后的作品。同步保存跨截止时，资产绑定事务回滚后在事务外保留已胜出的取消 / 超时结论。仅清理此任务临时 part，保留共享物理资产与其他任务引用。
- 逻辑名额与真实 IO 分开跟踪。取消后的未退出请求仍在 inFlight 内；每类最多允许 5 个真实操作，避免不响应中止的替身 / 系统操作无限堆积。真实 IO 达到保护上限时，队列等待其收尾；两类保护互不占用。DNS 本身不可强制中止，但其 await 后再次检查信号和截止，不能迟到发起 fetch。
- 单任务取消、超时和预期终态竞争不关闭整个调度器。定时器发生数据库写失败进入统一存储故障处理、停止入场并中止可停止的请求，不能从 timer 逃逸成 uncaughtException，也不假造成功超时记录。
- stop-polling 仅暂停查询，保留当前名额和原截止；resume-polling 只允许未结束 / 未过期的同一个 ID。Retry-After、原失败次数和查询预算保留，并受剩余总预算限制；暂停状态同样会到期释放名额。

## 下载尝试与下一批 DTO

v8 追加 task_download_attempts，保存独立 id、started_at、deadline_at、timeout_seconds、outcome、finished_at 和每任务唯一活动尝试约束；追加本地终态不可变触发器。v1–v7 SQL/checksum 原样保留，复用一致备份、SHA256、事务和回滚体系。

retry-download 只使用已有安全来源或原 ID 的 GET 刷新，不重新生成。下载尝试使用显式操作时配置的独立预算；原生成 executionAttemptId / deadlineAt / localOutcome / localFinishedAt 保留。每类名额已满时返回 TASK_CAPACITY_BUSY，请用户稍后重试；不另建无限下载池。下载尝试中断重启后明确失败，不静默重试。

共享 DTO 位置：backend/tasks/lifecycle-contract.js 的 taskFields；backend/storage/store.js 的 record 连接最新下载尝试；frontend/src/lib/workbench-task-client.ts 的 DownloadAttemptDto / DurableTaskFields。

- localOutcome / localFinishedAt 始终表达原生成执行结论；下载失败后的显式重试成功，也不重写原生成失败结论。
- downloadAttempt = null 或 `{id,active,startedAt,deadlineAt,timeoutSeconds,outcome,finishedAt}`。active=true、outcome=null 表示独立下载正在等待 / 运行；其终态为 completed / failed / timed_out / cancelled。
- localExecutionActive 是本地是否仍有可取消执行；generationReserved 包含活动下载尝试使用的同类名额。
- I05 不得仅凭原 localOutcome 非空允许移除活动下载尝试；I07 不得仅凭它禁用取消或认定当前下载已经结束，应同时消费 localExecutionActive 与 downloadAttempt.active / outcome。
- 对经过异步预检但尚未派发的瞬间，底层 status 仍为 local_queued；I07 应按实际执行 / 名额字段解释这个过渡阶段，不把它显示成已发送的模型进度。
- 本批提供最小执行阶段与终止原因，I06 仍负责完整阶段事件、时长汇总和脱敏诊断导出；本批没有宣称 I06 完成。

## 恢复与更新

- 旧无 attempt/deadline 的活动图片 / 视频，包括无 ID 的 submission_unknown 和有 ID 的 polling_paused，只做一次本地恢复结束，保留真实 ID、远端未知、旧输入 / 去重凭据；不补造旧时限，不 POST，不静默 GET。连续 recover / 重启不重复追加终态事件。
- 未派发队列保留 requiresContinue，用户明确继续后才派发。原无时限队列在新的真实派发边界采用当时设置建立新 attempt/deadline，不修改旧输入和空的创建快照列。
- 新视频有 ID、未过期时恢复为 requiresContinue 的暂停记录，显式恢复同 ID 只使用剩余预算。无 ID 且确实无法继续原请求的新记录，准确结束本地等待并保留 unknown；不能借恢复重新生成。
- 新任务已有安全结果源且未过期，重启后下载也须显式 continue-queued；只用剩余预算。仅内存签名 URL 丢失且无 ID 时，明确 RESULT_NOT_RECOVERABLE，不能伪造可恢复来源。
- prepareUpdate 先阻止派发；任何真实请求、下载、收尾或数据库相关活动未退出均返回 UPDATE_BUSY。仅内存结果继续保留 UPDATE_UNSAVED_RESULT 保护。安全 persistUpdatePause 停止轮询、持久队列继续要求并停止运行计时器，再由原更新退出逻辑关闭数据库；未改 desktop 更新 / 发布实现。
