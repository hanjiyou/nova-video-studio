## 1. 实际行为

图片/视频共用“作品名称（选填）”，名称与分组/模式草稿一起持久保存。当前名称优先用于最近任务、全部任务、作品库、预览和详情，原提示词完整保留；旧作品不操作时延续原展示和原文件。名称最多60个Unicode字符，允许重复，名称不发送上游。

作品库搜索按空白拆词，顺序不限，每词均须匹配同一作品当前名称、提示词或模型中的任意字段。保留日期、分组、类型和分页；改名后不匹配当前查询的作品从列表移出，计数同步。

新作品首次输出使用名称、原创建时间、稳定防重编号与真实扩展名；无名沿用提示词摘要。旧作品明确补名、新旧作品修改名称，均同步正式输出文件名；清空名称回到提示词摘要命名。多输出整体处理，冲突自动追加编号且不覆盖。已分配时间与输出序号保持稳定，重新下载继续使用登记位置。

重命名入口覆盖作品库更多菜单、预览与任务详情。真实生成/下载/文件IO在途时禁止改名；操作中锁定重复请求。回执丢失复用原请求核对；名称版本冲突提供“读取最新作品信息（保留输入）”，用户核对后再保存。视频在改名前释放播放源，关闭弹窗仅恢复源，不自动播放。

另存副本通过assetId/taskId核对正式输出关联后给出当前名称默认值，路径选择和覆盖确认仍由系统对话框处理。无作品上下文的参考素材保持单参数接口。

## 2. 数据和文件安全

只追加schema v14，v1–v13 SQL/checksum保持不变；原备份、事务和失败回滚流程继续使用。任务当前名、原提交名、名称revision独立；旧输入省略workName仍保持原结构与去重事实，改名不改变原生成意图或增加生成POST。HTTP/WS统一投影名称，主会话补齐完成/失败作品的实时订阅保留。

复用group_file_operations操作日志，先校验副本，事务绑定全部输出及检查点，再清理独占原文件。其他任务输入、草稿、待提交意图、结果候选及物理别名引用保留原文件和ID；必要时为当前作品建立独立文件。未提交阶段失败回滚，提交后清理失败返回cleanupPending，准确提示“名称与文件名已更新，旧文件整理尚待恢复”。外部替换过的目标不删除。

旧摘要文件在原目录补名，新增named_legacy显式受管标志；未登记的可读旧路径依然拒绝访问，父目录联接/符号链接仍校验。原摘要素材继续按SHA去重，已命名旧作品允许相同字节的独立文件，避免共享引用阻止改名。用户导入原件和应用外部副本不随本操作改名。
