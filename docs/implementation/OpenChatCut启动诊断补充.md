## 触发背景与结论

用户安装版曾提示打开剪辑超时，随后重试成功。此前宿主丢弃子进程stderr，也没有服务/页面/界面阶段日志，不能据此确定原故障根因。本批补足可观察性，保持整体启动30秒、页面加载后编辑界面等待10秒预算；不以延长超时掩盖问题，也不宣称已经修复或证实原故障。

日志位于Nova应用数据目录的`editor-diagnostics.json`，GitHub Test默认路径为`%APPDATA%\Nova Studio GitHub Test\editor-diagnostics.json`。每次新打开有独立attemptId，进程sessionId用于跨启动区分。此文件本批独立保留，尚未合入设置页“导出脱敏诊断”。

## 记录内容及使用方式

| 末端事件/阶段 | 可以确认的范围 |
| --- | --- |
| preflight_failed | 运行资源、版本或依赖预检未通过，查看受控code |
| service-start超时，尚无entry | 子进程已启动但服务入口阶段尚未报告；不能直接认定某依赖加载失败 |
| service-start超时，已有imports/plugins/projects/listen等 | 服务最后报告的初始化阶段及持续时间 |
| service_ready后停在page-load | 服务已就绪，页面加载尚未完成 |
| page_loaded后停在shell-ready | HTML已加载，原版shell/library/timeline尚未全部挂载 |
| shell_ready/startup_completed | 原版界面就绪，不仅是HTTP页面返回成功 |
| renderer_gone/service_exit | 已观察到的渲染/服务退出类别、退出码与信号 |

同时记录页面网络错误码、固定错误名/系统码、控制台和stderr类别、关闭/强制结束，以及总耗时和阶段耗时。晚到的子进程事件留在原attempt；重置View后的晚到加载完成不会混入下一次打开。仍可能需要系统事件或更具体的隔离复现才能确定外部根因。

最多240事件，历史读取上限192KiB，每次打开最多8个控制台错误。stderr至多16KiB仅暂存内存用于分类，磁盘仅记录类别、已知错误码和字节数。事件白名单不接受原文错误/堆栈、URL、真实路径、工程名、提示词、Key或媒体内容。采用随机独占临时文件和原子替换，拒绝符号链接目标；写入失败不影响剪辑。
