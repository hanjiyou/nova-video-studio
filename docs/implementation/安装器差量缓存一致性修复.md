# 安装器差量缓存一致性修复

日期：2026-10-27。状态：实现完成，缓存专项和真实 Electron 离线传输通过，主会话另有独立复核；未提交、推送、发布或真实安装。

## 原因与修改

electron-builder 26.15.3 的 NsisTarget.configureDefinesForAllTypeOfInstaller 使用 package.name 推导 APP_INSTALLER_STORE_FILE=nova-image-updater\installer.exe；原有 afterPack 仅把 app-update.yml 改为按渠道区分的 appId-updater。安装器保留基础包与运行时读取基础包因此断链。原生 copyFile 仅执行 CreateDirectory/ClearErrors/CopyFiles /SILENT，未核验覆盖或处理失败，仅修改 YAML 不能修复。

新增受支持的 nsis.include 宏：customHeader 把原生复制目标改为 APP_ID-updater\installer.next.exe；customInit 在复制前检查固定目录和文件类型，并在可用时持有目录句柄；customInstall 先失效旧记录和索引，再明确覆盖复制、对比源与 staging 的 SHA512、原子替换 installer.exe，最后写入最小 installer-state.json。记录仅含 schemaVersion/appId/version/sha512（十六进制）。源就是最终缓存基础包时保留已验证源，避免替换正在执行的 EXE。

危险路径（reparse point、固定文件是目录）提前拒绝。普通缓存写入或复制失败不令应用安装失败，不建立新的可信记录。卸载编译排除缓存变量、回调和动作；继续包含原有资料保留宏。完成页设置、package.name、appId、产品名、资料目录不在本修复中改动。

新增 desktop/update-cache.cjs。validateInstallerCache({cacheDirectory,appId,version}) 异步校验固定记录和基础包；prepareInstallerCache 进一步失效可信基线所在渠道的根 current.blockmap。没有可信基线时返回安全枚举，让本次更新直接完整下载；不扫描、不搬运其他缓存，不读取 pending 包作为已安装基础包，不新增联网恢复机制。

必须在可信基线下失效根索引的原因：electron-updater 6.8.11 在下载结束、尚未安装时便把 pending 的新索引提升到根。下一次下载可能因此把新索引配到旧基础包。prepare 删除的只有这个固定根索引，由既有更新器按当前 app.version 获取对应旧索引；失效失败则保守完整下载。pending 与其他渠道保持。原生最终安装包 SHA512 校验及差量失败的全量回退继续生效。

下载前集成、状态显示及诊断由另一实施单元负责，见 [状态与诊断记录](安装包差量更新状态与诊断.md)。
