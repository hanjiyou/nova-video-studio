## 4. 里程碑与审查门槛

| 里程碑 | 必须有的证据 | 不通过时的处理 |
| --- | --- | --- |
| M0 | 原版启动/打包、测试基线、契约与模拟服务 | 优先解决底座问题，不继续堆功能 |
| M1 | 无自动重复 POST、持久数据、凭据与重启恢复 | 不接真实生成链路 |
| M2 | 图片/视频请求 fixture、原始双图字节、自动下载本地文件 | 不把界面成功当接口完成 |
| M3 | 四页可操作、引导、三模式、作品库与复用 | 按 61 项补齐交互 |
| M4 | 故障回归、真实线路能力与剩余限制 | 必要时由主会话裁定范围变化 |
| M5 | 实际 Windows 安装包与最终验收报告 | 有缺项则如实保留未完成状态 |

## 5. 实施代理交接及汇报格式

首次派工只下发 T00–T01，验证底座后由主会话审阅再下发后续任务；不要求用户逐项重复批准已经授权的日常实现。涉及产品范围改变、无法验证的能力或新增付费测试范围，回到主会话处理。

派工必须包含：模型 `gpt-6.1-sol`、推理 `xhigh`、仓库路径、三份规划文档、负责的任务和文件边界、现有变更清单、禁止覆盖他人修改、验收标准及反馈渠道。后续优先复用同一实施代理。

每个任务结束报告：

1. 完成的任务 ID 与功能编号、实际diff和修改文件；审核前保留未提交，不用提交标识代替待审查状态。
2. 执行命令、退出码、测试/构建证据和产物路径。
3. 哪些仅由模拟验证，哪些已真实验证，哪些仍未知。
4. 未解决的问题及影响，不以“代码已写”代替完成。
5. 下一任务是否满足前置条件、是否需要主会话作出决策。

状态流转为：待开始 → 进行中 → 待审查 → 已验收；遇阻另记阻塞原因。主会话负责审核与方案调整，应用代码改动由实施代理完成。
