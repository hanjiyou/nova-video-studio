# 发布校验改为服务器摘要优先

日期：2026-11-02。状态：当前源码、回归及文档已完成；本次交付范围仅提交推送脚本与文档，不重新打包/发布。已发布3.6.11保持原资产与源码绑定，原交付记录不改写。

## 行为

此前正式脚本默认将三份资产下载回来计算SHA512。3.6.11当次按用户选择通过受控续跑做服务器SHA-256核对，但该方式当时没有进入正式脚本；本次将其固化为默认策略。

- `scripts/release-windows-update.cjs`在完整本地包验证后，一次流式读取同时计算本地SHA256和SHA512。默认`auto`逐件核对GitHub返回的严格SHA-256、大小、名称及uploaded状态；相等时不下载远端文件。
- 摘要字段缺失、null或空字符串时，沿用完整下载、大小和SHA512核对。格式畸形、未知算法或摘要不一致直接停止，不降级掩盖异常。`--verification full-download`保留主动完整回读，并仍拒绝服务器摘要不一致。
- 原源码/版本/稳定draft/tag、签名及正式门槛、同号不覆盖、上传前先验已有资产、续跑与凭据边界保持。缓存键包含校验模式和两种本地摘要，摘要优先的结论不会被完整下载模式借用；每次仍读取当前身份和资产元数据。
- 日志和`remoteVerification`区分服务器摘要、完整下载、回退原因及同次复用。`scripts/deliver.cjs`向草稿和发布阶段透传策略，并保存实际逐件回执；菜单第3项不必额外操作。仅本地打包入口拒绝该发布参数。

旧独立构建目录继续使用其绑定提交中的脚本；新策略需要纳入后续已审核源码交付。安装包及客户端更新下载器不需要因此重打包或变更。3.6.11当次使用临时续跑的事实见[原交付记录](3.6.11-交付记录.md)。
