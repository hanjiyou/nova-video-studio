# G02–G04 分组工作台前端实施记录

日期：2026-10-27。状态：前端已实现并完成本记录所列离线验证，交主会话最终审核；未提交、推送、打包、发布、安装或真实生成。本记录不替代后端文件迁移、中文路径真实文件IO及安装态验收。

## 最终实现

- 生成页保留左参数、右预览、下最近任务结构；增加所属剧本和当前根目录下的实际新任务图片/视频目录。默认未分组；草稿按组与模式隔离，切组先可靠保存原草稿，保存失败保留输入；切换锁防止重叠请求、导入中切组及迟到旧组回调。载入/重读采用组、请求代次和对象身份门闩。已删除的启动分组明确恢复未分组并修复设置；IO失败不伪装成已恢复，归档分组草稿可读但阻止新生成。
- 提交和本地重复意图指纹包含组身份；已提交指纹按组与模式独立保存。最近任务服务端按当前组查询，保持既有视频默认6、可配置1–100和图片显示6条；快切组/类型/数量的旧响应不得覆盖新列表与预览。
- 作品库使用服务端 `scope=library` 完整保存结果语义，移除任务状态筛选，加入分组侧栏与服务端分组/类型/搜索联合过滤；保留分页、独立图片选择及已有双击/键盘预览。缺失/损坏标记依赖正式保存事实 `savedAt` 与输出可用性，后续重下失败不会掩盖既有成品异常。删掉当前筛选组后，仅在权威组列表到达时重置筛选和页码。
- 最近区提供全部任务弹窗，按组和全部/进行中/未完成/已完成请求服务端分页；未知回执、查询暂停、下载恢复入口仍可访问，未作分页后本地过滤。
- 拖拽与菜单使用同一改组客户端，发送 `groupRevision` 而非任务revision。正在执行、写入、迁移或需要恢复的任务/分组拒绝操作；同组和全部作品无迁移。收到明确拒绝后可新建操作意图，传输或未知回执保留原requestId与参数。输出按整条任务归组，显示实际原根目录及成功后的实际位置。
- 改组完成事件按原输出顺序映射新assetId，保持已选参考图顺序；菜单与拖拽均适用。打开中的预览同步新任务/素材并释放旧视频源。单纯选参考图不切换编辑器剧本。
- 分组管理包含新建、重命名、归档/取消归档、空组删除及显式历史整理。删除活动编辑器所属空组前保存并切到未分组、持久化设置，再请求后端删除。系统组不开放破坏性管理，具体冲突/占用/恢复错误使用中文。
- 历史整理先读取可审范围，展示逐任务源/目标路径与冲突；明确选择后执行，显示真实成功/失败数与逐项原因。部分失败保留失败选择，下一次明确执行使用新requestId；回执未知时锁定原范围并核对同一请求。恢复横幅按受影响组展示，提供 `POST /groups/recover {}`，不会假称全部恢复。
- 作品和任务复用实际MediaTaskCard，16:9封面cover、完整预览contain；实际时长/输出数，提示词两行、完整型号title、图标中文状态和固定操作区。生成卡无虚构百分比；已知大小显示真实字节/百分比、5px紫色圆角progress与速度，未知总量没有百分比；停滞/失联/非传输阶段速度为0。校验/保存独立于100%下载，失败原因、恢复入口及远端可能计费警告保留，详细时限仍在详情。
- 最后两处通知修正仅涉及MediaTaskCard与DownloadStatus：前者只在自己的task对象变化时响应任务通知，后者同时核对自己的task与下载请求pending变化，保留回执防重复行为并减少无关卡片更新。

## 过程失败与修正记录

- 初期以根目录启动新增Vitest文件，未使用frontend别名配置，发生模块解析失败；切回frontend目录后正常。初期旧LP状态筛选/隐藏文案与同步模式切换断言按新确认行为更新，未删除实际预览、选择、分页和保存断言。
- 新组测试一处可访问名称空格不匹配、测试mock类型两处错误已修正；最终类型检查与测试通过。
- 首次扩展弹窗截图脚本以DOM对象作为CDP按值返回条件，出现 `Object reference chain is too long`；改为布尔就绪条件后通过，未据此修改产品UI。
- 早一轮受影响148项记录为147通过、1项多页参考图选择 `STACK_TRACE_ERROR`，原始[失败结果](grouped-workspace-frontend-tests.json)保留。该文件隔离复跑4/4通过，多页选择约4.2秒；随后两处通知订阅限定自身，并以2个worker复跑最终148/148，多页选择约4.58秒。没有足够证据将首次失败归因于单一原因，也不宣称此次修正已证明测试耗时改善。
- 既有生命周期回归存在React `act` 提醒，不能把无失败等同于完全没有测试警告；最终JSON保留测试范围事实。
